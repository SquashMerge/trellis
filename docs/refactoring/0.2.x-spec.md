# 0.2.x refactoring spec: layer deviations and complexity

**Status:** accepted by the owner on 2026-11-13 with the rulings in section 10, and revised after the reviewer's findings on #983 (section 11). Accepted items become issues on the 0.2.x milestone. It supersedes the baseline in #163.

**Scope:** all three apps in the repository: `trellis` (Rust), `trellis-web` (`web/`) and `trellis-herdr-mod` (`herdr-mod/`).

**Goal:** reduce deviations from the layered architecture and reduce file and function complexity, without changing behaviour. Zero deviations is the aim where it is worth its cost; where it is not, this spec says so and proposes a reasoned exception instead.

**Baseline:** `main` at v0.2.0 (`d84f264a`), index pin `221d2b8e-b5ee-4480-8319-670c30cf2a16:4`, rust-analyzer and scip-typescript evidence fresh. Measured with Trellis's own tools (`trellis rules check`, `trellis metrics`, the MCP navigation tools). Section 9 lists what the tools could not answer.

The detailed evidence is in three appendices:

- [Appendix A: storage layer](0.2.x/appendix-a-storage.md): responsibility map of `src/store.rs` and `src/store/**`, classification of every deviating pair, step-by-step plan.
- [Appendix B: Rust complexity](0.2.x/appendix-b-rust-complexity.md): diagnosis and decomposition of each hot function, file splits with line ranges.
- [Appendix C: web and herdr-mod](0.2.x/appendix-c-js.md): module structure, duplication, hot functions, `app.js` split.

The 129 deviating pairs are listed in [`baseline-deviations.txt`](0.2.x/baseline-deviations.txt). The appendices are analysis notes. They mark what was not verified, and their "after" complexity figures are estimates. This document is the proposal.

## 1. Summary

1. **One structural cause explains most deviations.** 107 of the 129 deviating file pairs (899 of 940 references) start in the storage layer. `Store` is the application facade: entry code asks it for finished views, and it runs query and indexing code to build them. The query layer references storage 13 times; storage references query 425 times.
2. **That cause splits into three fixes:** move view assembly up into query (353 references), move persisted record types down into shared (about 200), and move the pieces of the indexing pipeline that live under `store` up into indexing (about 230).
3. **About 215 references can be removed by moving types and constants alone**, with no behavioural code touched. That is most of the first phase.
4. **Almost all deviations can be removed** with 15 storage steps and 2 small-edge fixes. Two candidate steps cost more than they return and are deferred; their roughly 48 references stay as known deviations under a ratchet. Exceptions are recorded only for the validation call and eight test-only references.
5. **Complexity is concentrated.** 18 Rust functions and 5 web functions score cognitive 100 or more. The largest Rust files are mostly in-file tests: moving test modules out of ten files is a pure move of about 15,700 lines.
6. **Some of the worst code is dead or test-only.** `finish_rejoin` (cognitive 150, 18 parameters) is reached only from the test-support oracle, and about 150 lines of its chain never run.
7. **The JS apps report zero deviations for the wrong reason.** Each is one layer, and `web/` has no module system, so Trellis sees no references inside it. This spec does not propose layers for `web/` until the check can see its structure.
8. **Guardrails come with the work:** a rules-check ratchet (local verify and nightly) so the deviation count can only fall, and a complexity ceiling for new and changed code.

### 3.2 Complexity

| Option | Rule for new and changed code | End state |
|---|---|---|
| A | No function at cognitive ≥ 50 or ≥ 300 lines; no file ≥ 4,000 lines. Existing offenders go on an allowlist that may only shrink | none |
| **B (ruled)** | As A | No function at cognitive ≥ 75 or ≥ 400 lines outside the named allowlist below; every Rust file under 3,000 production lines except `store.rs`; no JS function ≥ 60; every JS file under 1,000 lines |

Option A's allowlist would start at 78 Rust functions and 33 web functions. Option C would catch 257 Rust functions today and is not worth its cost.

**The allowlist for option B's end state is these six,** each for a reason given in 5.3: `scip_raw::wire`, `dependency_rust::build`, `dependency_rust::index_package`, `RetainedStageContinuation::advance_unit`, `settle_document`, `finish_rejoin`. Everything else above the line has scheduled work.

**`store.rs` is outside the file cap.** S5–S10 take it from about 22,700 production lines to roughly 11,000, still far above 3,000. Splitting what remains is not scheduled here; it is planned when phase 3 is measured. Code is not moved only to satisfy a count.

Two rules apply whichever option is chosen:

- A closure counts against its enclosing named function, so moving a body into a closure does not pass the gate. Module wrappers (the IIFE around a classic script) and `create`-style factories in the JS apps are not functions for this rule; the file cap holds them.
- File size is measured on production lines, or after the test-module moves (R1), so the cap does not mostly measure test volume.

Enforcing the ceiling needs a Trellis query that does not exist yet (section 9, gap 6; #989).

## 4. Diagnosis

### 4.1 Storage: three causes

Detail and evidence: Appendix A.

**Cause 1: `Store` is the application facade.** Entry code holds a `Store`, calls `evidence_response()` and then view-shaped methods: `sequence_at`, `navigation_at`, `classes_at`, `architecture_response_at`, `metrics_at_prepared`, `mcp_search_candidates`. The query modules are a pure projection library; the code that loads rows, calls the library and shapes the answer lives under `store`. Three files under `src/store/` contain no SQL at all (`sequence_hops.rs`, `graph_read/sequence_callbacks.rs`, and `architecture_core.rs`, whose `compute` "touches no SQLite" by its own doc). This is 29 pairs and 353 references.

**Cause 2: persisted record types are defined beside the code that produces them.** `native_evidence.rs:276-550` (`DocumentKey`, `Declaration`, `Call`, `DeclarationRole`, …) and the record types at the top of `semantic_evidence.rs` are exactly what storage encodes and decodes, but they sit in 6,531- and 3,431-line indexing files. The same holds for capture records, `IndexOptions`, `semantic_batch::limits`, `skipped_config`, `BoundaryReason` and the search candidate types. This is 38 pairs and about 200 references, plus roughly half of the 81 references from `store.rs` to `capture.rs`.

**Cause 3: part of the indexing pipeline lives under `store`, in mutual recursion with indexing.** `store/native_first/**` is the semantic catch-up unit: `index_coordinator` calls into it, it drives `semantic_import` and `semantic_batch`, and those call back into `store.with_native_reader`. `store.rs` also runs capture and extraction itself during recovery, and holds incremental-preparation functions that only `index_coordinator.rs` calls. This is 41 pairs and about 230 references.

**A storage core already exists.** About 8,900 lines of `store.rs` and 5,800 lines of its submodules have no upward reference today, and about 9,500 more reference only record types. That is a core of roughly 24–25k lines, interleaved with about 7k lines of view assembly and 4.5k of pipeline.

### 4.3 Rust complexity

Detail: Appendix B.

- **In-file tests inflate the largest files:** 74% of `mcp/projection.rs`, 53% of `scip_raw.rs`, 52% of `daemon/search_fill.rs`, 51% of `mcp/tools.rs`, 35% of `native_evidence.rs`.
- **The rejoin chain is not production code.** `rejoin_inventory` is called only from `src/store/native_first/oracle.rs` (gated on `test-support`) and tests. Inside it, `rejoin_inventory_with_reuse` is always passed `None`, so `reuse_captured_source_associations` and the branch at `semantic_import.rs:3878-3923` are dead.
- **Dispatch functions are big matches with policy scattered through them:** `run_call` (1,117 lines), `provisioned_core_answer` (900), `dispatch_connection` (803), `tools::check`, `dispatch_cli`. They do not share a shape; each has its own fix.
- **State machines run in one function:** `coordinate`, `unit`, `advance_unit`, the `advance` steppers. The transferable fix is a phase enum with one `step_*` function per phase.
- **Shared abstractions that look tempting and are not real:** a trait over the four reference catalogs, a stepper trait, a handler table across the dispatchers. Do not build them.
- **Real, smaller duplicates:** Python and JS star-import precompute; `DeclarationId` four times and `charge` three times in `references/*`; three interval-index copies; metrics option validation in three places; about 85 near-verbatim lines between `JoinContinuation::advance` and `join_staged_using`.

### 4.4 Web and herdr-mod

Detail: Appendix C.

- **`web/` is 15 classic scripts sharing globals.** An implicit layering exists (vendor, pure, Pele adapters, view controllers, shell, composition root) and is mostly followed.
- **A cycle through the top of the stack:** `IndexPin` is defined in `app.js` and read by five lower modules (36 uses). Five tests regex-extract it from source.
- **Shell and views depend on each other:** `architecture.js`, `treemap.js` and `viewer-metrics.js` call `TrellisShell`, and the shell calls back into `TrellisSequence`, `TrellisClasses` and `TrellisNavigation`.
- **A global-scope collision:** `sourceWitness` is declared at top level in both `sequence.js:7` and `app.js:1194`. The bodies are identical today. There are five copies in all.
- **Duplicated SVG admission.** `validatedSvg` exists in four adapters with the same 15–20 line admission prefix. `sequence-pele.js` lacks the pre-parse rejection of active markup that the other three have, and the three patterns differ from each other. The post-parse allowlist still rejects those elements, so this is an inconsistency, not a hole.
- **The mod already reuses web's projection code** by bundling eight `web/` scripts unchanged. Three of those files mix a pure half with a DOM controller, so the mod loads whole controllers with a fake `document`.
- **Drifted copy:** the mod's `indexLabel` no longer matches web's `checkoutIndexLabel`.
- **A test-only mode:** the non-`display` path in `architecture-pele.js` `project` and `validatedSvg` is not reached from either web call site, and the mod also always passes `display` (`herdr-mod/src/diagram.js:125-129`, through web's `createDisplay`).

**How S5–S7 stay behaviour-preserving.** Rust allows inherent `impl` blocks for a type anywhere in the crate, so `impl EvidenceResponse { pub fn sequence_at(..) }` can move to a query-layer file with no call-site change. The methods keep running inside the response's snapshot, so no transaction or fence changes.

**Two honest limits of that mechanism:**

- It is unverified that the rules check attributes a relocated `impl` method to its new file. S5 verifies this first; if it does not, S5–S7 need free functions or extension traits instead, which changes call sites.
- After S5–S7 the query layer calls widened storage helpers and contains SQL. The deviation count falls, but the boundary is nominal until S14. The owner decides S14 after phase 2, when the width of the helper surface is known, and leans toward building the row API.

**Test coupling applies to every move out of `store`.** 36 `*_tests.rs` files (13,846 lines) and about 5,400 inline test lines reach `store` privates through `use super::*`. A moved function's tests move with it or keep working through a `pub(crate) use` shim. Tests that pin only the old location of a private are rewritten.

## 8. How each step is verified

- **Behaviour:** `./tools/verify`, `cargo fmt --all -- --check` and clippy on the pinned toolchain, as for any change. A pure move changes no test expectation; if it does, it is not a pure move.
- **Deviations:** `trellis rules check` before and after, on fresh semantic evidence. The PR states pairs and references removed, and G1's recorded count is lowered in the same PR.
- **Complexity:** `trellis metrics` for the touched files before and after. The PR states the measured figures; the estimates in this spec are not acceptance criteria.
- **Stored and wire formats:** S1b–S4b move serde types. The encoding shape is unchanged: existing golden and fixture tests pass, with no schema or `toolVersion` bump.
- **Build-input identity:** `build/extractor_inputs.rs` and `build/semantic_join_inputs.rs` hash explicit source paths and bytes (Decisions 0005 and 0021 D4). Every move out of a listed file (S1–S4b, S9, R1, R17) updates those manifests and the guards in `src/extractor_inputs_tests.rs` and `src/semantic_join_inputs_tests.rs`, so moved code stays covered. A pure move may therefore rotate a digest, and the existing contracts apply. Native extractor-hash drift follows Decision 0005: full measurement, extraction and validation, keeping the generation, old pins and `requests.db`. Join-digest drift misses the old payload reuse key and requires new validated settlement under Decision 0021 D4. Neither recreates the index; recreation remains the separate schema-incompatibility path. Hashes are not frozen and nothing is migrated to avoid a rotation.
- **Coordination code** (S9, S10, R8, R9, R16): preserved are sole-worker authority, old-root settlement before reconciliation and FIFO, the FIFO and watcher order, bounded semantic units with no snapshot held across selection, the MCP cancellation, deadline and root checks at send, and `Reservation` lifetimes and high-water behaviour. These steps move or extract code and do not reorder it. A test that pins only incidental error precedence is not a contract; CLAUDE.md's correctness and cheap-stability rules decide.

## 9. Trellis gaps found while doing this

The analysis was done with Trellis's own tools wherever they could answer. These are the places they could not; each is a candidate issue.

**Bugs**

1. **`trellis metrics --scope file|directory|declaration` is unusable from the CLI.** `src/main.rs:1304` and `:3447` accept only the old `source-set:v1:path-<hex>` ID form and reject current IDs with `invalid_argument: source set ID`. Per-function metrics were read from the browser API instead.
2. **`trellis_rules_explain` with `limit: 50` returned 5 evidence entries and `omittedEvidence: 0`** for a pair with 85 references.
3. **`use super::*` produces deviating pairs.** Six of the 107 storage pairs are one-reference glob imports of a name the file never uses.
4. **`maxNesting` counts `else if` chain length** (and probably closures and `let … else`): `drive` reports 13 against about 7 by reading.
5. **Feature gating is invisible.** Callers under `#[cfg(feature = "test-support")]` are labelled production, and `#[cfg(test)]` references count as production deviations.

**Missing capabilities**

6. **No revision-wide "worst functions" query.** `topCognitive` is capped at 10 per scope and is not exposed in the CLI or MCP. The baseline needed 226 per-file requests. G2 needs this.
7. **No per-declaration breakdown of a rule instance.** "Which methods of `impl Store` reference layer X" is the core question for a 23,000-line file; evidence is per file pair.
8. **Rule evidence has no compact form:** about 2 KB per entry.
9. **Closures are anonymous declarations.** They cannot be looked up, are not attributed to their enclosing function, and are not added to its complexity.
10. **References between classic scripts through `window` globals are invisible**, so `web/` has no reference graph.
11. **`incoming_calls` is name-matched**, and merges all same-named declarations (14 `advance` methods; four `validatedSvg`).
12. **Reads fail during a publication** (`rebuild_in_progress`, `store_unavailable`) with no fallback to the previous head. The automatic producer re-import blocked two of the three analyses mid-session.
13. **`compact: true` responses are 17–40 KB**, mostly `scopeCoverage` for unrelated languages.
14. **No file outline, duplication detection, same-name-collision check, or "reachable from non-test code" query.**
