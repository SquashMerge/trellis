# MCP read-only pilot: first-release wire contract

**Status: normative five-tool read-only MCP wire contract, implemented.** [Decision 0007](semantic-evidence/decisions/0007-user-daemon-and-workspace-selection.md) makes `trellis mcp` a thin stdio client of the per-user daemon, with explicit same-repository worktree selection; #107 amends the schemas below. [Decision 0008](semantic-evidence/decisions/0008-daemon-sole-writer.md) makes that daemon the only index and queue writer; [Decision 0009](semantic-evidence/decisions/0009-checkout-worker.md) assigns each active checkout one worker, pipelines relay calls, starts deadlines at protocol acceptance and sets the capacity and pre-resolution failure shape below. This is the agent-facing projection of [#22 semantic evidence](semantic-evidence/contract-v1.md) and [#23 local topology](local-topology.md). #22 owns evidence meaning, identity, validity, coverage and provenance; #23 owns coherent snapshot eligibility. This document owns only the wire projection. The configured client launches `trellis mcp` for one workspace selected by [#23 discovery](local-topology.md#workspace-discovery). The OS user, not an MCP principal or grant, is the boundary. No network listener, authentication role, ACP permission or tool annotation enforces access. Configuring an agent can disclose indexed checkout text to that agent/provider; repository text is untrusted data.

All five tools use cached index state, never live files. An admitted evidence read keeps one selected snapshot through response finish; describe can instead report not-ready status with a null basis. They never request indexing, start a producer/build, run repository code, open a terminal, invoke a provider or make a durable write. The daemon checkout worker alone owns mandatory startup reconciliation (H), watcher capture, publication and FIFO work; `catchingUp` reports pending work without waiving validated-head or root checks. No storage table, class or implementation mechanism is prescribed. The catalog order is `trellis_workspace_describe`, `trellis_find_symbols`, `trellis_declaration`, `trellis_outgoing_calls`, `trellis_read_source`. Declaration and outgoing calls are separate closed tools, not views of an inspect tool; `trellis_inspect` is not recognized. Source uses the selected stored raw BLOB, verifies its path/version and whole-file hash/length before slicing, then strictly decodes only the requested LF-delimited range. This selected MCP source exception preserves the existing public `source_at` and other native-reader witness attestation; it is not a disk fallback.

## Protocol, negotiation and transport

Normative modern revision: [official MCP 2026-07-28, commit `0cb6c6a31768cbb16129b35e6b569a31fecfe1b6`](https://github.com/modelcontextprotocol/specification/blob/0cb6c6a31768cbb16129b35e6b569a31fecfe1b6/docs/specification/2026-07-28/basic/index.mdx#L322-L409); see [discovery](https://github.com/modelcontextprotocol/specification/blob/0cb6c6a31768cbb16129b35e6b569a31fecfe1b6/docs/specification/2026-07-28/server/discover.mdx#L7-L59), [schema](https://github.com/modelcontextprotocol/specification/blob/0cb6c6a31768cbb16129b35e6b569a31fecfe1b6/schema/2026-07-28/schema.ts#L35-L110) and [stdio](https://github.com/modelcontextprotocol/specification/blob/0cb6c6a31768cbb16129b35e6b569a31fecfe1b6/docs/specification/2026-07-28/basic/transports/stdio.mdx#L7-L85). Support **exactly one** legacy revision, `2025-11-25`; no general older-SDK guarantee.

Use one newline-delimited UTF-8 JSON-RPC 2.0 message per line, **not** Content-Length framing. Stdout carries protocol messages only, stderr diagnostics only. Reject batches. IDs are non-null strings or safe integers; a string ID is admitted only when its decoded value, reserialized as one canonical compact JSON string token including the surrounding quotes, is at most 256 UTF-8 bytes. To form that token, wrap the decoded value in `"`; escape `"` as `\"` and backslash as `\\`; escape U+0008, U+0009, U+000A, U+000C and U+000D as `\b`, `\t`, `\n`, `\f` and `\r`, respectively; escape other U+0000–U+001F scalars as lowercase six-byte `\u00xx`; emit every other Unicode scalar directly as UTF-8, with no normalization or optional escaping. Measure the reserialized token, not the incoming escape spelling or Unicode scalar count. An oversized string ID receives a bounded JSON-RPC `-32600` response with `id:null` before connection-mode selection or pending-request registration; do not echo the ID. Numeric IDs retain their existing rule, and the full-line request cap still applies. An outstanding ID cannot be reused. EOF cancels outstanding work and exits. Do not promise detecting client `kill -9` while another process keeps stdin open. A valid `notifications/cancelled` has `{requestId,reason?:string}`; suppress every further response for that outstanding request, even a tool error. Ignore unknown/completed IDs and unknown notifications without responses. Cancellation overrides an unsent result. **Decision point (owner ruling 2026-10-11, #127):** a relay that holds a complete result settles every input frame the client finished writing before it decides, so any such cancel suppresses that result. A cancel written after the decision is concurrent with the result: the result is written once and the late cancel produces no output, as MCP clients already ignore responses to requests they cancelled. The settling wait counts only input written before the decision, so later input cannot delay a result; if it cannot settle within a bounded time, answer `outcome_unknown` instead of the result. Under Decision 0009, the relay pipelines calls, so the decision point applies **per client ID**. It covers every decided outcome, including the relay's own `deadline_exceeded`, and for a call its settling wait ends by that call's deadline. On the daemon connection, the relay uses its own monotonic IDs, so a late daemon reply never matches a client ID reused after its outcome was written. Cancellation is forwarded to the daemon instead of closing the connection. ("Mandatory H" below is Decision 0009's startup reconciliation.)

Modern mode has **no** initialize/initialized exchange. Each request has `params._meta` with literal keys `"io.modelcontextprotocol/protocolVersion":"2026-07-28"` and `"io.modelcontextprotocol/clientCapabilities":{}` (or valid capabilities); optional `"io.modelcontextprotocol/clientInfo"` follows MCP `Implementation`. These are single namespaced keys, not dotted nested objects. Notifications need no request metadata. `server/discover` takes only this protocol `_meta` and returns exactly `{resultType:"complete",ttlMs:0,cacheScope:"private",supportedVersions:["2026-07-28","2025-11-25"],capabilities:{tools:{}},_meta:{"io.modelcontextprotocol/serverInfo":{name:"trellis",version:<build-version>}}}`. The modern server identity is in result `_meta`, **not** top-level `serverInfo`; legacy `initialize` below uses its separate top-level field. Omit instructions; modern discovery and list results use required `ttlMs:0,cacheScope:"private"` caching hints, so a client may re-fetch instead of sharing any workspace-specific result. Advertise no subscriptions, sampling, elicitation, prompts, resources, tasks or client roots; empty client capabilities suffice.

In modern mode, `tools/list` takes only protocol metadata and returns `{resultType:"complete",ttlMs:0,cacheScope:"private",tools:[<five catalog entries>]}`; after legacy initialization it takes no parameters and returns `{tools:[<five catalog entries>]}`. Both list five entries in catalog order without pagination or next cursor; supplied cursor is a protocol parameter error. Each entry has its closed input schema below and an output schema that is the success/error envelope union. Each advertises `readOnlyHint:true`, `destructiveHint:false`, `idempotentHint:true`, `openWorldHint:false`. These are hints, not permissions or a promise that repeat reads have the same basis. `tools/call` takes `{name,arguments,_meta}` in modern mode and `{name,arguments}` in legacy mode. Both success and failure tool results contain `{resultType:"complete",isError:<boolean>,structuredContent:<full envelope>,content:[{type:"text",text:<summary>}]}` in modern mode; legacy results omit only `resultType`. `structuredContent` alone conforms to the tool’s closed output schema. The text is a deterministic UTF-8 summary of at most 512 bytes, **not** a JSON copy. Success uses `<tool>: <count> <items>[, truncated: <reason>]; full result in structuredContent.`; failure uses `<tool> failed: <code>: <message>`. Counts are one workspace for describe, the emitted number of symbols for find, one declaration for declaration, the emitted number of calls for outgoing, and the selected number of lines for read_source. Thus the item words are `workspace`, `symbols`, `declaration`, `calls`, and `lines`, respectively. The optional truncation clause appears only when `truncated:true`, and uses the exact `truncationReason`. Keep the full envelope, its evidence and all omission counts in `structuredContent`. Count the complete result, including both structured content and summary text plus LF, toward the 65536-byte frame cap.

Legacy mode starts with MCP `initialize` carrying `protocolVersion`, `capabilities`, `clientInfo`; respond with `protocolVersion:"2025-11-25"`, `capabilities:{tools:{}}`, `serverInfo:{name:"trellis",version:<build-version>}`. A different requested revision receives this supported revision per legacy negotiation; an incompatible client must disconnect. Wait for `notifications/initialized` before list/call; then use negotiated connection state, not modern required metadata. Repeated initialize and premature tool requests fail `-32600`. Select connection mode on the first valid modern request or initialize; reject switching modes. Cancellation remains available during work.

| Protocol condition | JSON-RPC error |
| --- | --- |
| Malformed JSON or UTF-8 | `-32700` |
| Invalid JSON-RPC shape, batches, oversized input, lifecycle violation | `-32600` |
| Unknown method | `-32601` |

For `-32022`, include required JSON-RPC `error.data:{supported:["2026-07-28","2025-11-25"],requested:<requested-version>}` so the client can negotiate; the requested value is the unsupported revision received. `-32021` is reserved for genuinely required missing client capability (none here); `-32020` HeaderMismatch does not apply to stdio. Bad **application** arguments to a known tool instead return the typed error envelope. Oversized wire input is discarded through its line delimiter and receives bounded `-32600`; malformed parsing has `-32700` precedence when no valid request was obtained.

## Shared schema and limits

Every application object is closed: unknown fields fail. All fields are required unless marked `?` optional; a nullable field is **present**, with null allowed. Explicit null is invalid for an optional non-null input. JSON `UInt` is `[0,2^53-1]`; strings contain valid Unicode scalars; byte limits count UTF-8, never characters. Import #22's [Text, Language, Kind, Range, SyntaxId, OccurrenceId](semantic-evidence/contract-v1.md#conventions-and-shared-types), [DocumentKey, Coverage, Provenance, SemanticBasis](semantic-evidence/contract-v1.md#identity-and-coverage), [freshness](semantic-evidence/contract-v1.md#basis-and-freshness), [Declaration](semantic-evidence/contract-v1.md#records-and-bindings), [CallBinding](semantic-evidence/contract-v1.md#dispatch), [Hash](semantic-evidence/contract-v1.md#conventions-and-shared-types) and [canonical IDs](semantic-evidence/contract-v1.md#stable-identifiers), and [warnings-v1](semantic-evidence/contract-v1.md#warning-completeness-warnings-v1) without redefining their nested fields or invariants. `Range` is zero-based, half-open, UTF-8 scalar-aligned. A symbol ID is canonical `sid:v1:` plus 32 lowercase hex digits; examples below use illustrative valid-shaped IDs, **not** #22 identity vectors.

| Wire type | Exact shape and rule |
| --- | --- |
| `Basis` | `{indexGeneration:string,indexRevision:UInt}`; generation is fresh on creation/rebuild, non-nil lowercase canonical UUID; revision advances per successful publication. Not #22 revision ID: the snapshot unambiguously maps to each evidence record's source-set/revision identity; inconsistent mapping fails `store_unavailable`. |
| `Evidence` | `{evidenceTier:"syntax"\|"semantic",semanticBasis:SemanticBasis\|null,freshness:"fresh"\|"possiblyStale"\|"stale"\|"unavailable",staleBecause:string[]}`. Successful first-release value is **only** `syntax,null,fresh,[]`, relative to eligible captured snapshot, not instantaneous disk. No unavailable placeholder or promised schema-compatible automatic semantic expansion. |
| `DocumentRef` | `{ref:UInt,document:DocumentKey,revisionId:Text,contentHash:Hash,provenanceId:Text}`; the per-response table entry for one emitted document version. `ref` is contiguous from zero and is the value of an emitted item’s `doc`. |
| `Lines` | `{start:UInt,end:UInt}\|null`; non-null bounds are 1-based inclusive LF-delimited source lines, with `1<=start<=end`. Null is reserved for a zero-length range in an empty cached file. |
| `Symbol` | `{symbolId:SyntaxId,name:Text\|null,displayKey:Text,kind:Kind,doc:UInt,range:Range,nameRange:Range\|null,lines:Lines,...Evidence}`; `displayKey` is the selected declaration’s qualified presentation label defined below, never an ID or lookup proof. `doc` supplies the selected declaration’s document version, whole-file content hash and native proof. Preserve #22 name/nullability and identity. |
| `NativeCandidate` | `{syntaxId:SyntaxId,name:Text,doc:UInt,range:Range}`; fields project one verified fresh native `Declaration` in the eligible response snapshot. Its `doc` entry’s `provenanceId` equals that declaration’s verified native proof, not a borrowed match proof. `name` and its language-decoded lookup key are non-null; this is a lexical hint, **not** a `Target` or binding. Candidates have no `lines`. |
| `NativeCandidates` | `{items:NativeCandidate[],omitted:UInt\|null,complete:false}`; required on every outgoing `CallItem`, at most eight items. An integer counts exact verified eligible matches not shown for **that emitted call**; null means optional hint matching/count did not finish within its separate work budget and requires `items:[]`. `complete:false` is invariant. Excluded calls and unknown matches are never counted. |
| `Warning` | `{code:"coverageIncomplete"\|"staleEvidence"\|"staleTarget"\|"bindingAmbiguous"\|"syntaxOnly",message:Text,provenanceId:Text\|null}`. |
| `Limits` | `{requestBytes:16384,responseBytes:65536,sourceBytes:16384,sourceLines:200,defaultLimit:20,maxLimit:50,calleeTextBytes:1024,hintWorkMs:1000,deadlineMs:5000,concurrency:4}`. |

For W2–W4, `documents:DocumentRef[]` is a **wire projection**, not an amendment to #22 `Declaration` or #22 proof semantics. Each `doc` resolves to exactly one entry with matching `ref`; no entry is unused. Build the table from exactly the distinct document versions used by **emitted** symbol, declaration, call and shown candidate `doc` fields, not the searched scope, an omitted prefix, or the selected owner present only in outgoing coverage/provenance. An empty emitted item set has `documents:[]` even if owner closure remains. Identity is the full `DocumentKey` (`language`, `sourceSetId`, `path`) plus `revisionId`, never path alone. A different content hash or provenance proof for the same identity is `store_unavailable`, not an arbitrary ref choice. Sort identities by `(language in #22 order: java, rust, python, javascript; sourceSetId bytes; path bytes; revisionId bytes)` and assign `ref` and matching `doc` as consecutive zero-based integers. Equal snapshot and request yield byte-identical table, refs and serialization. This table replaces only the named duplicate item fields: Symbol's `document,contentHash,provenanceId`; declaration data's outer `contentHash` and nested Declaration's `document,revisionId,provenanceId`; CallItem's `document,revisionId,contentHash,provenanceId`; and NativeCandidate's `document,revisionId,provenanceId`. Do **not** compact `Provenance.document` or coverage tuples: keep their full #22 shapes, sorting and actual proof. Every item range and evidence remains unchanged.

`lines` describes an item’s own `range` in its `doc` entry's selected cached raw BLOB, without opening a live file or decoding unrelated source. For a nonempty byte range use the LF-delimited line containing `range.start` and the line containing `range.end-1`; for a zero-length range use the line at `range.start`. At EOF of a nonempty BLOB, use its last selectable line, even if the final LF ends the file; do not invent a post-LF line. An empty BLOB's zero-length range has `lines:null`. No UTF-8 decoding is needed to locate LF boundaries. A same-`evidenceBasis` and same-`contentHash` W5 read of `path` from the referenced `DocumentRef` using the returned inclusive `lines` has a `byteRange` containing the item’s range **if** the selected slice has at most 200 lines, at most 16384 raw bytes and is valid UTF-8. Otherwise retain non-null `lines`, and W5's existing `range_too_large` or `unsupported_encoding` applies; multiple bounded reads may cover a long range collectively, but one over-cap read is not claimed to contain it. Empty-BLOB null is exempt. W5 path lookup and its guards must still select and verify that same document version or return its existing typed failure; a path alone is not license to substitute a different source set.

Qualified `displayKey` for a measured declaration `d` is `d.document.path + "#" + join(".", ancestorSegments + [ownSegment])`: each outer-to-inner ancestor segment is its measured `Key.name` or, when null, `Key.kind + "@" + decimal(Key.ordinal)`; the own segment is `d.name` or, when null, `d.kind + "@" + decimal(d.range.start)`. Preserve path/name bytes with no normalization or inferred scope. For example `src/a/Invoice.java#Invoice.total` is a readable label; unnamed declarations use their measured fallback. The label is always `Text` when required selected declaration evidence is valid, but it is **not unique** (Java overloads may share it), is never parsed as an ID, and never enters requests, hashes, lookup, ranking, ordering, joins, resolution or completeness. An unavailable/malformed required selected declaration is `store_unavailable`, not a null or fabricated label.

Workspace selection applies to the five tool calls only; discovery and list remain workspace-independent. All five flat input schemas retain `additionalProperties:false`; the declaration and outgoing-call inputs are separate closed objects, with optional `workspace` alongside their own fields. There is no inspect union or `view` discriminator. The MCP client resolves its launch checkout from `--workspace` or the nearest Git checkout from its launch directory. Omitted `workspace` selects that launch checkout. An explicit `workspace` is a verified absolute directory path (at most 4096 UTF-8 bytes), resolved to a checkout root without silently following a symlink to a different selection. The daemon checks the selected root's identity and that its verified Git common directory is the same as the launch checkout's; nearby paths or equal markers do not establish membership. A different repository or unverifiable path is refused, never answered from the launch checkout instead. Selection attaches the worktree through the MCP session's lifetime. Each admitted evidence result uses one checkout and one coherent, committed and validated snapshot; no evidence from different worktrees mixes. Describe may instead report no ready head. A valid prior head remains readable during startup reconciliation, watcher work or pending FIFO requests with `catchingUp` sampled at read admission; it does not promise current-disk freshness or authorize an unvalidated head. With no valid head, evidence reads return `index_not_ready`. Root identity is checked before admission and at the daemon send decision.

Success envelope for a **resolved** checkout: `{schemaVersion:1,requestId,workspace:string,catchingUp:boolean,evidenceBasis:Basis|null,data,warnings:Warning[],partial:boolean,truncated:boolean,truncationReason:null|"response_bytes"|"limit"|"callee_text"}`. `workspace` is the answering checkout's verified absolute root, never its label or the caller's unverified input. `catchingUp` is sampled with that checkout's read admission. `requestId` equals the outer JSON-RPC ID. Only describe may succeed with a null basis. There is no `ok` wrapper. Resolved failure: `{schemaVersion:1,requestId,workspace:string,catchingUp:boolean,error:{code,message,retryable,currentBasis:Basis|null,currentContentHash:Hash|null}}`, without success fields or evidence, and `isError:true`. A non-null current basis is safely verified eligible; otherwise null. A non-null current hash occurs **only** for a hash mismatch at a found cached path, never from disk. `checkout_capacity` is a resolved-checkout error when a verified selection cannot acquire one of the 64 active-checkout slots.

Selection failure has no answering checkout: `{schemaVersion:1,requestId,error:{code:"workspace_selection_failed",message,retryable,reason,attemptedWorkspace,currentBasis:null,currentContentHash:null}}`. Reasons are `not_absolute`, `not_checkout`, `different_repository`, `identity_changed`, `unavailable`; only `unavailable` is retryable. An omitted selection whose launch checkout cannot be verified also fails without answering attribution; `attemptedWorkspace` describes its attempted launch path. A non-string `workspace` on a known tool is instead **application** `invalid_request` with `{schemaVersion:1,requestId,error:{code:"invalid_request",message,retryable:false,attemptedWorkspace,currentBasis:null,currentContentHash:null}}`, never JSON-RPC `invalid_params`; neither failure has `workspace` or `catchingUp`. `attemptedWorkspace` is closed and bounded: string input becomes `{kind:"path",value:string,utf8Bytes:UInt,truncated:boolean}`, where `value` is the first at most 256 UTF-8 bytes cut at a Unicode scalar boundary, `utf8Bytes` is the exact input byte count, and `truncated` reports clipping. Short absolute paths are retained exactly. A string longer than 4096 UTF-8 bytes fails `invalid_request` with that tag rather than selecting its truncated prefix. Non-string input becomes `{kind:"invalid_type",jsonType:"null"|"boolean"|"number"|"array"|"object"}`; never serialize a raw array/object or stringify it ambiguously. These are the only additions to the closed failure `error` object: `reason` occurs only for `workspace_selection_failed`, and `attemptedWorkspace` occurs on selection failure and invalid-type/oversize `workspace` failure. Other bad application fields retain their existing error and precedence; they do not claim a checkout unless one has already been resolved. A known tool's malformed application arguments still use a tool envelope; protocol-only errors remain JSON-RPC errors. `daemon_unavailable` is retryable; `outcome_unknown` is not automatically retryable and requires request/job status inspection rather than replaying an ambiguous mutation.

Find, declaration and outgoing-call data objects contain `coverage:Coverage[]` and `provenance:Provenance[]`. Declaration coverage contains the selected declaration’s relevant native tuples; outgoing-call coverage contains those of the selected declaration, emitted measured calls and shown `nativeCandidates` declarations. Find coverage contains the native tuples of the documents of the **emitted** symbols only, keyed by full `DocumentKey`, revision and producer, deduplicated (amended by #156, owner-ratified 2026-10-16); the searched scope is reported as aggregate `scopeCoverage` counts (W2). Provenance is the complete closure for returned evidence, including returned symbols, the selected declaration, emitted calls and shown native-candidate declarations; do not fabricate it for the name-match relation, failed extraction or negative search. Sort coverage by `(producerId,language,sourceSetId,documentPath,revisionId)` with #22 enum/byte order and provenance by ID. Missing required rows, corrupt digests or mixed revisions are hard failures (`store_unavailable`), never best-effort warnings. Describe and read_source have neither array.

## Tool catalog

### `trellis_workspace_describe` (W1)

Input exactly `{schemaVersion:1,workspace?:string}`; no pins or indexing flags. Data exactly `{workspaceLabel:Text,indexState:"indexing"|"reconciling"|"ready"|"unavailable",progress:{completed:UInt,total:UInt|null}|null,watcherDegraded:boolean,languages:LanguageStatus[],toolVersion:1,schemaVersion:1,limits:Limits}`. Label is not an absolute path. `completed<=total` when total known; progress null if ready, unavailable or unmeasured. `LanguageStatus={language:Language,evidenceTier:"syntax",coverage:{selected:UInt,complete:UInt,partial:UInt,failed:UInt,unselected:UInt}}`; these count native coverage tuples, **not** universal language capabilities, and complete+partial+failed=selected. When ready return exactly four languages in #22 order (java, rust, python, javascript), even with zero counts. Otherwise `languages:[]`, null basis, no previous coverage advertised as current. Describe warnings=[], truncated=false, truncationReason=null; partial iff not ready or any selected partial/failed count is nonzero.

### `trellis_find_symbols` (W2)

Input `{schemaVersion:1,workspace?:string,query:string,limit?:UInt,expectedBasis?:Basis}`. Query is 1–256 UTF-8 bytes, literal name/ID substring: no trimming, regex, glob, wildcard or Unicode normalization. Use SQLite built-in ASCII `lower` and literal `instr`. Default limit 20; accepted 1–50. Search all admitted source sets/documents at one eligible snapshot, with no path/language/source-set filter. Rank exact case-folded name, name prefix, other name/ID substring; ID-only is rank three. Tie-break original name (null first), then ID in UTF-8/ASCII byte order. Fetch one extra match to detect omitted rows. Data exactly `{symbols:Symbol[],documents:DocumentRef[],coverage:Coverage[],scopeCoverage:LanguageStatus[],provenance:Provenance[]}` (amended by #156, owner-ratified 2026-10-16). No snippets or bodies.

- **`scopeCoverage`** reuses describe's `LanguageStatus`: exactly four entries in #22 order (java, rust, python, javascript), including zero counts. Counts come from **all native coverage tuples** in the same eligible find snapshot, across every searched source set, independent of query, limit and response-byte clipping. `selected=complete+partial+failed`; `unselected` counts notRequested, omitted and unsupported tuples; the total is `selected+unselected`, with no separate field. These are tuple counts, not symbol counts or universal language support. Never join a separately sampled describe result.
- **`coverage`** is the sorted, deduplicated native coverage closure of the **emitted** symbols only, keyed by full `DocumentKey`, revision and producer. It excludes the limit+1 lookahead and any symbol removed for response bytes. **`provenance`** is the complete closure for those emitted symbols. Zero emitted symbols means `documents`, `coverage` and `provenance` are all empty.
- **Completeness:** any selected partial or failed tuple anywhere in the searched scope (from `scopeCoverage`) makes find `partial:true` and adds one aggregate `coverageIncomplete` warning before `syntaxOnly`, even on zero hits or with healthy hits elsewhere. Truncation also makes it partial. Unselected-only tuples do neither, but `unselected>0` and a zero-hit result never prove universal absence. This find-only aggregate projection of warnings-v1 does not change declaration, outgoing_calls, read_source or #22 graph semantics.
- No hit is `symbols:[],documents:[]`, **not** not_found. Empty symbols cannot prove complete extraction.
- **Bounds:** the 65,536-byte cap applies to the whole structured-content-plus-summary JSON-RPC line, including LF and the four mandatory scope rows. Emit the longest fitting ordered symbol prefix and recompute its coverage, provenance and warnings. If the first hit cannot fit but the empty prefix does, return `symbols:[],documents:[]`, `truncated:true`, `truncationReason:"response_bytes"` (not a false negative). Only a fixed empty-prefix envelope that cannot fit is `range_too_large`. No pagination or path/kind filter.

### `trellis_declaration` (W3)

Input exactly `{schemaVersion:1,workspace?:string,symbolId:SyntaxId,expectedBasis?:Basis}`. `limit`, `view`, `depth`, graph budgets and all other extra fields fail `invalid_request`, not an empty projection. IDs retain an 8192-byte ceiling and must have canonical #22 syntax. Invalid syntax gives `invalid_request`; absent valid ID gives `not_found`.

Declaration data exactly `{declaration:WireDeclaration,displayKey:Text,doc:UInt,lines:Lines,evidence:Evidence,documents:DocumentRef[],coverage:Coverage[],provenance:Provenance[]}`. `WireDeclaration` projects the complete selected #22 `Declaration` **except** `document`, `revisionId` and `provenanceId`, supplied instead by the data-level `doc` entry; it retains `syntaxId,kind,name,lookupKey,ancestors,key,range,nameRange,header` and their nested #22 shapes and measured array order. Outer `contentHash` is supplied by that same entry. Its `displayKey` is the qualified label of the selected measured declaration, even when its name is null; it is presentation-only. `lines` covers the declaration's `range`. ## Result completeness, bounds and failure precedence

Find/declaration/outgoing `partial` iff truncated, returned selected coverage incomplete, or a returned boundary call. Thus nonempty syntax-only outgoing calls are partial without a dedicated warning. Source success is never partial/truncated; describe follows its status rule. For evidence responses apply [#22 warnings-v1](semantic-evidence/contract-v1.md#warning-completeness-warnings-v1) with selection `semanticProducerId=null`: `syntaxOnly/null` is required even for empty find and source. Selected failed/partial coverage adds `coverageIncomplete/null`. Other triggers are #22 stale provenance per ID, possiblyStale aggregate/null, staleTarget per binding provenance and ambiguous binding per provenance; unreachable under valid fresh syntax-only first release. Deduplicate `(code,provenanceId)`; order by declared enum **coverageIncomplete, staleEvidence, staleTarget, bindingAmbiguous, syntaxOnly**, then null-before-text provenance and message. No unresolved/unsupported/truncation warning.

Request cap 16384 bytes counts UTF-8 JSON-RPC line excluding delimiter. Response cap 65536 counts the **complete serialized JSON-RPC line including full `structuredContent`, the summary text block and the LF delimiter**. The cap applies to every response except `tools/list`. The catalog is static and authored by Trellis, not derived from repository content, so its complete line, including LF, has its own **catalog cap of 262144 bytes** (#165); a test keeps the catalog at least 16384 bytes under it. `Limits.responseBytes` describes the 65536-byte cap that bounds tool results. For lists choose the longest fitting ordered item prefix and recompute its emitted-only document table/refs, required coverage/provenance closure, warnings and omission counts for each prefix; never trim identity, mandatory coverage or provenance. Find's entire searched-scope `scopeCoverage` is fixed overhead, even for zero hits. For outgoing, first choose the longest ordered **call** prefix that fits with each `nativeCandidates.items:[]`, each emitted call’s exact known `omitted` count or null budget result, the emitted-call document table and mandatory closure. Calls excluded from that prefix contribute nothing to `omitted`. Then fill candidate prefixes for calls with known counts in call order (each at most eight) while reserializing the **whole JSON-RPC line including structured content, summary text and LF** and adding shown declarations' document refs, required coverage/provenance closure; a null-count call keeps its items empty. Stop the global candidate prefix at the first item that would exceed 65536 bytes; count that and all remaining verified eligible items for emitted calls as omitted. Never drop an already selected call or required closure just to show a hint. If fixed coverage/envelope, or the first required call and its empty candidate object/closure, cannot fit, return `range_too_large`; never shrink a searched scope or report a falsely complete empty result. A shown item never lacks its native closure. Single-object/source outputs fail rather than truncate. A call or candidate omitted for response bytes sets `truncated:true` and reason `response_bytes`; a call or candidate omitted for its limit sets `truncated:true` and reason `limit`. Any **known** omitted candidate sets `partial:true`; a null omitted count alone does not assert truncation, a warning or additional partiality (a returned unresolved boundary call already has `partial:true`). `complete:false` stays invariant even with zero known omissions. Truncation reason priority is `response_bytes`, then `limit`, then `callee_text`. Exactly meeting a cap is not truncated; clipped callee sets partial/truncated even when all call rows fit. Candidate omission adds **no warning**.

**Admission and limits (Decision 0009 §7):**
- **Deadline:** a `tools/call`'s five-second deadline starts at **protocol acceptance**, when the relay (or the daemon session, for a direct socket client) reads the complete valid call. It covers application validation, capacity, selection, read admission, the read and the send decision.
- **Capacity:** after application validation, a connection may have at most four outstanding calls, and a fifth receives `too_many_requests` without queueing. The daemon also runs at most 16 live call-worker threads; a worker keeps its permit until its thread exits, even after its call timed out or was cancelled. Exhausting that budget, or failing to start a thread, also gives `too_many_requests`.
- **The send decision:** the daemon rechecks cancellation, then the deadline, then selected-root identity. The relay decides each call's client-facing outcome by its own acceptance plus five seconds. The bound covers that decision, not a client that stops reading stdout.
- **After the deadline:** if mandatory call/read work exceeds it, return `deadline_exceeded` with no partial evidence unless cancellation suppresses output. Optional hint work stops at its separate budget instead of failing the call.

Before read admission has sampled `catchingUp`, a `too_many_requests` or `deadline_exceeded` uses the pre-resolution failure shape:

`{schemaVersion:1,requestId,error:{code,message,retryable:true,attemptedWorkspace,currentBasis:null,currentContentHash:null}}`

`attemptedWorkspace` is the selected string, or the launch workspace path when the selection is omitted, in the bounded `path` encoding. After read admission, `deadline_exceeded` keeps the resolved failure shape.

| Typed error code | Condition / retryability |
| --- | --- |
| `invalid_request` | Bad application field, path, ID, partial/malformed pin, reversed range; false |
| `range_too_large` | Numeric cap, source/response size, out-of-file range; false |
| `unsupported_encoding` | Selected cached source slice invalid UTF-8; false |
| `revision_conflict` | Complete basis or found cached path hash mismatch; false (change guards) |
| `index_not_ready` | No valid published head; true |
| `not_found` | Valid ID or cached path missing; false |
| `too_many_requests`, `deadline_exceeded` | Admission cap or deadline; true |
| `root_changed` | Opened workspace root pathname missing or its `(device,inode)` differs, including the final response check; false for this opened workspace, `currentBasis:null` |
| `store_unavailable` | Unsafe/unreadable/invalid store or missing required coverage; false (no automatic same-call retry) |
| `workspace_selection_failed` | No answering checkout; typed reason `not_absolute`, `not_checkout`, `different_repository`, `identity_changed` (false), or `unavailable` (true). Attempted workspace is bounded and tagged. |
| `checkout_capacity` | Verified checkout could not attach within the 64-active-checkout bound; true. |
| `daemon_unavailable` | Daemon connection/start/reconnect unavailable after bounded attempts; true. |
| `outcome_unknown` | Acknowledgement for an ambiguous mutation was lost; false, inspect request/job status instead of replaying automatically. |

The closed output-schema failure enum includes **all fourteen** codes above, including `unsupported_encoding`, `root_changed`, `workspace_selection_failed`, `checkout_capacity`, `daemon_unavailable` and `outcome_unknown`. Its closed top-level success and failure shapes have `workspace` and `catchingUp` only after resolution. Before resolution, ordinary argument failures (`invalid_request` or `range_too_large`) have neither answering fields nor an attempted workspace; invalid-workspace-type failures additionally include a tagged `attemptedWorkspace`. Selection and pre-resolution admission failures also have a tagged `attemptedWorkspace` and no answering fields. Each of these closed shapes is a branch of every tool's output schema, so `structuredContent` alone validates on either outcome. Sanitize error messages: no SQL, source, credentials or absolute roots. After protocol acceptance, validate application fields, then apply capacity (Decision 0009 §7), then check the opened root pathname and `(device,inode)` before read admission, readiness, basis comparison, object lookup, hash comparison and range/materialization, in that order; repeat the root check at final eligibility before sending. A moved/replaced/missing root at either check takes `root_changed` over a pin, lookup, or unsent success and returns `currentBasis:null`. Startup gives `index_not_ready` before comparing a complete pin; stale complete pin conflicts before not_found; hash guard follows successful cached path lookup. A selected encoding error is not store corruption and requests no repair. Cancellation overrides all unsent outcomes.

## Snapshot eligibility (W8)

Discover/list operate during startup. Describe reports status; evidence tools need an eligible snapshot. The daemon alone opens and writes the index and queue; its checkout worker owns startup reconciliation, publication and FIFO claims. For every daemon-routed evidence read, admit a committed, validated head for the selected checkout (including a valid prior head during startup reconciliation, watcher work or queued FIFO work). Check the opened root pathname against its captured `(device,inode)` before and after materializing one coherent SQLite snapshot, and check the selected root again at the daemon send decision. Discard rejected responses. A missing/replaced opened root returns `root_changed`, retryable=false with `currentBasis:null`; an unsafe, unreadable or invalid store returns `store_unavailable` with no rejected `currentBasis`; no valid published head returns `index_not_ready` with `currentBasis:null`. There is no leader/incarnation/follower check or predecessor permit. `catchingUp` is advisory, sampled at read admission; it neither invalidates a validated prior head nor authorizes an unvalidated one. A normal later publication does not invalidate a coherent in-flight snapshot whose root and selected-read checks pass; guards compare **inside that snapshot**. No mixed graph/source revision, historical fallback or linearizable filesystem freshness.

| Situation | Eligibility |
| --- | --- |
| Daemon unavailable | Connect/start fails with typed `daemon_unavailable`; no standalone index read. |
| Cold activation or reconciliation with no valid published head | Describe reports status; evidence returns `index_not_ready` with `currentBasis:null`. |
| Startup reconciliation, watcher work or pending FIFO with a valid prior head | Evidence may read that committed, validated head with `catchingUp:true`, subject to the same root and selected-read checks; this grants no queue-claim authority. |
| Startup reconciliation commits a new validated head | Subsequent reads can use the new coherent basis; a complete pin to the old basis conflicts. |
| Opened root pathname removed/moved/replaced, before or after materialization or at send decision | Discard evidence; `root_changed`, retryable=false and `currentBasis:null`. Do not follow the new occupant. |
| Unsafe/unreadable/invalid store at unchanged root | Discard evidence; `store_unavailable` with `currentBasis:null`. |
| Rebuild/new generation | Old complete generation pin conflicts at an eligible new basis; incompatible old store is never a fallback. |
| Normal publication while reading eligible revision R | In-flight response can remain at coherent R after publication R+1 if root and selected-read checks pass; pin compares at R. |
