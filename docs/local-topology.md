# Local index and agent topology

**Status: the local daemon, queue, reconciliation, watcher and read-only MCP tools are implemented.** This #23 topology remains the behavior contract, as amended by [Decision 0008](semantic-evidence/decisions/0008-daemon-sole-writer.md) and [Decision 0009](semantic-evidence/decisions/0009-checkout-worker.md). The owner accepted the direction on 2026-09-23. [#22](semantic-evidence/contract-v1.md) owns semantic identity and evidence meaning; [#24](https://github.com/SquashMerge/trellis/issues/24) owns MCP wire form. These are behavior requirements, not prescribed SQL schemas or internal tuning values. The error names below describe refusal outcomes, not a separate error API.

Each selected checkout has a disposable, path-keyed index outside the checkout. Its Git directory holds a workspace UUID used by shared native evidence identity; a non-Git root uses path identity. `trellis mcp` is a local stdio client of the per-user daemon. The daemon is the sole index and queue writer; one event-driven checkout worker owns startup reconciliation (formerly mandatory H), the watcher, publication, FIFO work, retention and GC for each active checkout. CLI and browser data operations route through that daemon, not a standalone leader or follower. The UUID marker is the sole permitted topology write into Git metadata, which can itself be inside the checkout.

<a id="threat-model"></a>
## T00 — Threat model

This section bounds what every Stage 2–4 implementation and review must defend against. A review finding outside this bound is not a blocker.

**In scope.** Implementations must handle these safely, failing closed where they can't:

- **Untrusted repository content.** Any source, configuration or manifest bytes, including pathological sizes, nesting and encodings. Parsing and extraction stay bounded and never crash the process.
- **Untrusted callers.** Requests to the daemon, browser API and MCP server are authenticated where the contract requires it, and bounded and validated.
- **Ordinary faults.** Crashes, power loss, partial writes, full disks, I/O and permission errors. Concurrent Trellis processes, stale pins, and races with ordinary edits, `git checkout` and similar tools.
- **Accidental corruption of state files.** SQLite integrity failures and rows that fail typed
  decoding or closed validation return the contract’s typed corrupt failure, never a partial
  or best-effort result. The sole additional exception for semantic search is a disposable
  optional vector-cache row that fails typed decoding: it is a specified cache miss under T02,
  counts as unembedded and is re-embedded outside the read. This exception does not cover
  database-level failures, index evidence, card facts or required proof rows.

**Out of scope.** Implementations need not defend against:

- A process running as the same user deliberately editing Trellis's state (`index.db`, `requests.db`, the fact cache, locks or markers), including consistent rewrites that pass integrity checks, such as a BLOB and its hash changed together, or extra rows inserted with valid foreign keys.
- Hostile replacement of filesystem ancestors by the same user (see T02).

A same-user process can already change the source, the binary and the configuration, so these defenses would add no security.

Accordingly, reads need not re-authenticate stored rows against captured source or the graph, the local database need not be signed or MACed, and reads need no per-field size caps beyond the existing request and response bounds. These remove requirements; they don't forbid existing read checks or relax paired-pin publication rules. Validation happens at capture and publication; reads decode strictly and reject what fails.

<a id="workspace-discovery"></a>
## T01 — Discovery and identity

An explicit `--workspace` selects exactly that directory, never an ancestor. Otherwise walk upward from cwd to the nearest `.git` entry; if none exists, select cwd. A malformed or inaccessible encountered marker is an error, not permission to search farther upward. Refuse implicit home or filesystem root; an explicit choice still must pass the security and storage-overlap checks. Run no Git subprocess. Require an existing readable directory, refuse a final-component symlink, canonicalize ancestors once, and require a valid UTF-8 absolute root. Capture the opened root's `(device,inode)`; check this identity throughout its lifetime.

`root-key` is the 64-digit lowercase hexadecimal SHA-256 of the canonical absolute root's UTF-8 bytes (no trailing slash except `/`, no case or Unicode normalization). Record and verify the full spelling, not only its hash: a different spelling at that key refuses `root_key_collision`. The key determines cache placement, not semantic evidence identity.

A `.git` marker is either a current-user-owned non-symlink directory or a current-user-owned, regular no-follow UTF-8 file of at most 4096 bytes. A file contains exactly `gitdir: ` followed by a nonempty path, with at most one final LF or CRLF; reject NUL, extra lines or whitespace. Resolve relative targets against the file's parent, normalize `.`/`..`, traverse without symlinks, and require an existing, readable current-user-owned directory. Main checkouts, linked worktrees, submodules and separate-git-dir checkouts use their *selected* Git directory, not `commondir`; separate worktrees have separate UUID markers.

The marker `<git-dir>/trellis/workspace-id` contains exactly 36 ASCII bytes of a lowercase hyphenated, non-nil UUID; new markers use UUIDv4. Its parent is private, and the marker is a private, current-user-owned, single-link regular file opened no-follow. Invalid ownership, permissions, type or bytes refuse `invalid_workspace_id` without replacement. Create only the missing `trellis` child under a verified existing Git directory; never manufacture Git ancestors. An exclusive file creation picks one UUID, and losing creators adopt that value. A transient short write by a competing creator can be retried briefly; a crash-left partial marker needs owner intervention, not regeneration. Before *any* creator or adopter acknowledges a valid UUID, it fsyncs the verified marker, its `trellis` directory and Git parent, in that order; failure refuses `workspace_id_not_durable`. This also lets an opener finish a prior creator's interrupted durability sequence.

The shared workspace identity is that UUID, or `path-<root-key>` without Git. A Git checkout move changes its index key but retains its UUID. A marker change during an open requires close/reopen, never silent redirection. Reject roots overlapping either fixed topology location or configured token paths, including aliases and ancestors.

## T02 — Locations and store responsibilities

`<cache>` and `<data>` are fixed per-user `ProjectDirs::from("dev", "squashmerge", "trellis").cache_dir()` and `.data_local_dir()`. If unavailable, refuse; there is no placement override or state migration. State directories are private and outside selected workspaces. Reject unsafe ownership, symlinks or unexpected file types rather than repairing them. Local OS filesystem locking, safe descriptor opens and durable writes are required; do not claim protection against hostile concurrent ancestor replacement by the same user.

| State | Fixed location | Required content/lifetime |
| --- | --- | --- |
| Derived index | `<cache>/indexes/<root-key>/index.db` | Root spelling/identity, schema and extractor compatibility, fresh generation and revision; captured source, graph and dependency evidence. Rebuildable. |
| Index use lock | `<cache>/indexes/<root-key>.lock` | Path-keyed; use lock beside protected directory to protect live openers during recreation and GC. |
| Explicit requests | `<cache>/indexes/<root-key>/requests.db` | Root identity and accepted ordered reconciliation requests; survives index rebuild, but is discarded with an obsolete index directory. |
| Optional facts | `<cache>/facts.db` | Path-neutral extracted facts keyed by language, extractor version, extraction context and content hash; misses/eviction must not change evidence. |
| Optional vectors | `<cache>/vectors.db` | One machine-wide cache keyed by `(modelId,cardHash)`; shared across worktrees and recreated indexes. Missing, evicted or decode-invalid rows change retrieval only and are reported in `searchIndex`, never native evidence. |
| Model weights | Explicitly configured external paths | A user-supplied copy of a Trellis-supported pinned model; verified before loading, never bundled or automatically downloaded. |
| Tokens | Explicitly configured external paths | Durable, outside topology ownership. |
| Producer state | `<cache>/producers/<root-key>/` | Private state of explicit semantic producer runs (#21), keyed like the index: `runs/<runId>/` (with `run.json`), `pickups/<generationId>/` and `pickup.json`. Each level is created lazily, 0700, owned by the current user and never a symlink; unsafe state is refused with `invalid_request: unsafe producer state`, never repaired. A run directory holds the controlled worktree and other producer-phase files only while the producer runs. The whole folder, `pickup.json` included, is disposable derived state that GC owns (T06; owner ruling 2026-10-30 (#21)): `pickup.json` lives until `--clear` removes it or GC removes the checkout's index with the folder. |

An index publication changes generation only on creation/rebuild, advances revision on successful publication, and exposes one coherent validated graph/source snapshot. A failure leaves the prior committed snapshot intact, but cannot make an incompatible or invalid snapshot servable. The fact cache cannot be authoritative: a missing, corrupt, conflicting or unavailable entry falls back to extraction or reports extraction failure, never substitutes fabricated evidence. #10 chooses its tables and indexes to meet [#22](semantic-evidence/contract-v1.md) and its query budgets; no generic record-envelope table or future artifact placeholder is reserved here.

Search-only native card facts and each declaration’s cardHash are stored per document version
in index.db; vectors are not. A separate head-only split-identifier FTS5 table contains only
current-head candidate rows. The transaction advancing the head updates its rows atomically
with the head, card hashes, captured source and evidence. Its BM25 statistics depend only on
that head, never retained/released revisions. Retention and GC do not change head scores.
This is a third FTS5 table: Decision 0013’s native_declaration_trigrams and graph_node_trigrams
remain separate literal candidate prefilters and are not replaced or used for search ranking.

The daemon alone writes vectors.db. One background embedding owner, shared by active checkouts,
uses one active model. It runs after publication and never delays publication, enters
T04’s FIFO stream or adds durable queue state. After restart it recomputes current-head misses.
Embedding uses its own low-priority thread, never holding locks needed by the checkout worker.
Inputs are token-budget-bounded before tokenization, batch size is capped, and cancellation is
honored between batches. The single owner reuses verified resident model weights and int8
head matrices. Model weights expire after 600 seconds with no query or fill work; each use
resets their idle timer. Each matrix expires 600 seconds after its last query use or publication.
Background fill does not reset a matrix's timer, and a running head is excluded from idle
eviction until its job ends. Model readiness pre-warms active-checkout head matrices; daemon startup
pre-warms at most the four most recently opened checkouts with last-opened time within
seven days, newest first with root-key byte-order ties. Existing index metadata is the
approved recency proxy; discovery is read-only, creates no MRU catalog, does not activate
checkouts or refresh open age, and never delays daemon socket acceptance. This startup
work runs below normal work and stops when matrix-cap admission fails, without evicting
matrices to warm another checkout. This is the
[#358 startup policy](https://github.com/SquashMerge/trellis/issues/358#issuecomment-6446057555).
Verification is reused per file identity and repeated on
change; loading remains lexical-only and explicit Metal errors do not fall back. This is the
[2026-10-26 owner ruling](https://github.com/SquashMerge/trellis/issues/211#issuecomment-6427400386),
which supersedes per-job weight drop. Catch embedder panics at the job boundary as typed search-coverage failure,
never index failure. Read calls never enqueue indexing or write vectors. Changed card bytes change cardHash;
changed model, prompt, quantization, dimensions or card format changes modelId. Old entries
need not be deleted on publication. Index recreation preserves the cache. The cache has a
1 GiB default cap and LRU eviction; entries use int8 vectors of at most 1024 dimensions, with
no full-dimension mode.

The [2026-10-27 owner amendment](https://github.com/SquashMerge/trellis/issues/358#issuecomment-6441405819)
adds a resident int8 matrix per head pin and active model under that same background fill
owner. New heads patch only changed document-version IDs from vectors.db; fill completion
tops up missing vectors. A query uses one immutable published matrix matching its admitted
pin for vector ranks and counts, with the same mandatory index snapshot. The
[#358 memory policy](https://github.com/SquashMerge/trellis/issues/358#issuecomment-6446057555)
caps aggregate resident and in-progress matrix allocations at 2 GiB, including replacement
work and staging buffers. Conservative estimated allocation capacity and bookkeeping are
charged before allocation, not only vector payload; this is not an exact process-RSS limit
and excludes model weights. Query use shares the owner's existing matrix charge, not a
second copy. Normal work uses LRU eviction of eligible matrices. The 600-second idle eviction also remains. A single head
that cannot fit is lexical-only. A first search without a warmed matrix returns complete
lexical results while the background owner builds. If no matching matrix is retained or
acquisition races with a head change, search also returns lexical-only without query
embedding or waiting for the owner, never streaming around the cap. These unavailable
results have null model identity, embedded:0, selected backend and unavailableReason:null;
mandatory declaration counts/lexical reads and typed observed storage faults are unchanged.
This supersedes the earlier missing-matrix streaming fallback. A valid retained matrix
survives backing-cache eviction; owner updates and residency changes may change retrieval between calls at one
basis. Scoring uses NEON/SIMD with a scalar fallback and the stored-norm dot product,
accepted by gold-set R@5/R@10/MRR non-regression, not bit parity. sqlite-vec is not adopted; existing bounds remain.

When reading vectors.db, a missing, evicted or typed-decode-invalid vector row is a specified
miss and is re-embedded by the background owner. A database-level failure, including integrity failure, schema
mismatch, unsafe/unreadable storage or I/O failure, instead fails search store_unavailable
with no hits; it never becomes a lexical-only success. Repair/recreation of this disposable
cache occurs outside the read. BUSY/LOCKED remains typed retried contention, not corruption,
cache unavailability or permission to return a best-effort result. Search gives optional
vector work a single 3,000ms budget from protocol acceptance within the unchanged 5,000ms
call deadline. On expiry, it stops the operation cooperatively and returns complete lexical
results with `searchIndex.state:"unavailable"` and reason `vector_budget_exceeded`; incomplete
vector results/counts are discarded. Optional-cache contention may consume that budget but
BUSY alone never triggers fallback. Actual observed database faults and mandatory index/FTS
contention retain their typed failures. No cancellation affects another query or background
fill. Query model inference is never detached to make a timeout appear complete. The
independent matrix build remains owned by the background fill owner and finishes/publishes
even after a query's vector-budget fallback or cancellation/drop; it is not detached query
inference. There is no per-vector checksum, signing or same-user tamper-detection requirement.

The model is local, pinned and in-process via Candle. One model is active at a time. Supported
models only: verify configured files against Trellis’s reviewed model pin; do not execute
upstream Python code. Unknown/mismatched or not-yet-loaded models give the search unavailable
state and lexical-only retrieval, not fabricated model identity. No weights are bundled and
there is no automatic download or first-scope fetch command. Configured model weights do not
expand T00’s threat model.

Backend selection defaults to automatic: Metal on a macOS build with the metal feature, CPU
elsewhere, including Linux/OrbStack. Automatic selection may fall back; an explicit Metal
request that cannot be honored returns a typed error, never silent CPU fallback. Search
reports the actually selected backend separately from vector completeness. Platform release
builds are tracked in #338, not specified here.

**Early generation-aware pin prerequisite (#37, owner decision 2026-09-25).** The disposable index stores a fresh random `indexGeneration` on first creation and every rebuild/recreation. Ordinary successful publication retains it and advances `indexRevision`. A revision pin is the complete pair `{indexGeneration,indexRevision}`: status and pinned read results report both; every pinned read and write compare-and-swap (including index publication) requires and atomically checks both. A bare numeric revision pin is invalid, not a fallback. After deletion of the index and its lock directory, a recreated index has a new generation, so an old pair conflicts even if its numeric revision recurs; a live compatible index retains ordinary paired compare-and-swap. Browser and CLI callers forward the pair. Do not place a durable revision allocator in facts, requests, UUID markers or lock files. #37 supplies only this early pin identity/comparison; #39 consumes it for full publication, rebuild and guarded revision checks.

**Retired state ([owner ruling 2026-10-24, #305](https://github.com/SquashMerge/trellis/issues/305#issuecomment-6394175295)).** Saved views, notes, their record databases and use locks, and Jev/ACP ledgers are no longer opened, read, written, scanned, migrated or deleted by Trellis. Existing `<data>/workspaces/<record-id>/workspace.db` files, sidecars, locks and configured provider trees remain in place and ignored. This retirement does not change #22 durable-anchor semantics or shared workspace UUID identity.

## T03 — Use locks, daemon ownership and reads

The daemon single-instance lock is the sole cross-process writer-election lock; there is no per-checkout leader election or follower mode. The separate per-checkout index use lock still protects live index and queue openers against exceptional recreation and GC; a registry lookup does not replace it. Index openers hold shared use while protected handles are open, and deletion/recreation needs verified exclusive use after closing protected handles. Locks sit beside protected directories; compare the held lock inode with its no-follow pathname after acquisition, and release/reopen if they differ. Busy use locks do not authorize deletion, forced eviction or a blocking upgrade. Never close a separate file descriptor on a live SQLite inode.

The per-user daemon alone writes `index.db` and `requests.db`. For each active checkout its worker alone settles old-root requests, runs mandatory startup reconciliation, watches, publishes, claims and completes requests, and runs retention and GC units. CLI, browser and MCP data operations connect to or start the daemon and never open the index as a standalone fallback. The checkout worker, not a per-checkout leader lock or incarnation marker, owns the in-process publication and claim sequence.

Every daemon-routed evidence read admits a committed, validated head (including a valid prior head while startup reconciliation, watcher work or queued work remains), from one coherent SQLite snapshot. That read checks the opened root’s captured `(device,inode)` against its pathname before and after materializing the answer; a selected MCP worktree also checks its selection identity and eligibility at send. Its `catchingUp` status is sampled at read admission and is advisory, not permission to serve unvalidated evidence or a claim that the index equals current disk contents. With no valid published head, evidence reads return `index_not_ready`; `trellis_workspace_describe` may instead report not-ready status with a null basis. A missing or replaced root yields `root_changed`. Root loss stops old-root work and reads; a replacement gets a fresh runtime rather than repointing the old one.

There is no cross-process takeover or predecessor read permit. On activation, or after a live root replacement through a fresh runtime, the worker opens the queue, confirms terminal settlement of foreign-root accepted rows, runs mandatory startup reconciliation to a validated head, and only then claims FIFO work. An ambiguous settlement COMMIT blocks progress until a re-read confirms the terminal outcome. A prior validated head may be read during reconciliation, but neither that admission nor `catchingUp` asserts instantaneous filesystem freshness.

## T04 — One native queue and explicit requests

The daemon checkout worker serializes startup reconciliation, watcher capture, publication and explicit FIFO requests in one native work stream. Explicit browser and CLI indexing requests enqueue durably in `requests.db`, even from inside the daemon; MCP read tools never schedule indexing. An accepted request has `queued → running → done | failed`. Mandatory startup reconciliation commits a validated head, or confirms that the validated head is unchanged (Decision 0006, amended 2026-10-20), before the first FIFO claim. Thereafter a FIFO row is followed by the watcher gate before the next row: in the Q2→watcher→Q1 sequence, pending watcher intent gets its reconciliation step before the next FIFO claim. `WATCH_ACK` means a verified capture covers the accepted generation (after changed options, a full inventory), not merely that a watcher callback arrived. One worker owns claims and publications; invalid input or unavailable/unsafe storage fails explicitly rather than claiming acceptance. A waiting client may stop waiting without cancelling accepted work.

Acceptance is durable before it is acknowledged. Only the checkout worker claims, executes and completes requests. On activation it opens the queue and confirms terminal old-root settlement before mandatory startup reconciliation and FIFO claims. If the daemon crashes, the next activation can reclaim a running request and repeat work. A crash after publication but before queue completion can advance revision again; it cannot roll back committed source state. Index publication and request completion need not be one cross-database transaction. Keep requests when rebuilding or exceptionally recreating *index.db*; removing an eligible obsolete index directory discards them. A completed row stays terminal, and waiters re-read the durable row after a confirmed terminal-commit signal rather than treating a wake as the result.

Every request records the `(device,inode)` of its submitted root. A worker detecting a missing or replaced root stops old-root work and confirms queued/running old-root rows terminal as `root_changed` before closing. A fresh runtime for a replacement root opens the queue, confirms settlement of foreign-root rows, reconciles the new root and only then claims FIFO. If a COMMIT is ambiguous, progress waits for a re-read confirming terminal rows; it cannot report success for an old-root request. With no activating checkout, pending rows remain until later activation or eligible GC discards their derived directory. A waiter whose captured root was lost reports `root_changed`; a later lookup for an ID discarded with the directory gets `not_found`. No durable handoff/quarantine state or owner lease is needed. Never execute an old-root request on a new occupant.

**Failure causes (#445).** A failed row's `error_code` is a stable code, optionally followed by `: ` and a reason, the shape `recovery_blocked: <reason>` already uses; no new column and no `requests.db` schema change. A request that fails while executing records its typed cause from a closed set. A SCIP admission, artifact or limit failure keeps its existing code, `invalid_request`, `invalid_artifact` or `limit_exceeded`, with the fixed detail Trellis spelled for it, such as `invalid_artifact: empty or reversed SCIP range` or `limit_exceeded: output bytes` (limit names included). A detail outside the closed list records `unlisted detail`. A SQLite full disk is `storage_full: database or disk is full`. Any other failure of an index request is `index_failed: internal error`; a semantic import request's other failures keep the typed codes under **Diagnostics classes** below (owner ruling 2026-10-30 (#21)). `revision_conflict` is unchanged. Repository content, paths and error chains never reach the row. Classifying a failure changes neither which failures happen nor their precedence. The CLI error reads `<code>: request <id> failed: <reason>`, and the browser job status's `error` object carries `code` and, when one is recorded, `reason`. Rows written before #445 keep their bare code.

**Diagnostics.** A terminal row keeps only the code and closed-set reason above. Setting `TRELLIS_INDEX_DIAGNOSTICS=1` in the daemon's environment makes it write best-effort `index-phase …` lines to stderr: phase markers, and the cause behind a failed request. It is opt-in, off by default, and changes no outcome; a closed stderr is ignored. It is a production troubleshooting switch, not test instrumentation, so it is not behind `test-support`.

**Diagnostics classes.** The classes are the seven codes `invalid_request`, `invalid_artifact`, `limit_exceeded`, `capture_unavailable`, `stale_basis`, `revision_conflict` and `root_changed`, plus `storage_full: database or disk is full` and `index_failed: internal error`. The reason is an entry of the closed list (`REASONS` in `src/store/requests/failure.rs`) or `unlisted detail`; a code with no detail stays bare. A semantic import request whose error is not a typed failure or a full disk parses its message as `<code>` or `<code>: <detail>` for one of the seven codes; any other message is `index_failed: internal error`. An index request gets the same `index_failed: internal error` spelling. The code never carries a path, a count or a message that varies between runs. A pickup that fails before its import request is queued records its typed code instead: when the first line of the error starts with `producer_output_missing`, `producer_output_invalid`, `limit_exceeded` or `invalid_request` before any `:`, that line truncated to its first 120 characters is the code, with no closed-list reason mapping.

**Producer runs (#21).** A producer run is an explicit owner request (`trellis producer run --plan-sha256`) and never enters the FIFO. The checkout's producer owner runs at most one at a time (`producer_busy` otherwise) and holds an admission lease for the run. Only its generated import enters the FIFO, with a generated origin (T09). The watcher, the MCP server and daemon launch never start a producer. A client that disconnects does not cancel its run. `producer cancel` stops a run while it is materializing, running or writing its batch; once the import request is enqueued it answers `not_cancellable`, and the import's own request row is the outcome. Retirement or loss of the checkout's root cancels the active run, which finishes as `root_changed`.

## T05 — Watch, capture, reassembly and publication

The native source walker uses the established `ignore`-crate exclusions: no symlink traversal, hidden and common build/vendor directory exclusions, and supported `js,mjs,cjs,rs,java,py` extensions, subject to #22 source-set admission. In-root `.gitignore`/`.ignore` matter; ambient ancestor/global ignore rules and Git `info/exclude` must not silently influence a captured root. Record captured source bytes/hash and relevant admission, ignore, project config/manifest, toolchain and dependency inputs needed for an honest #22 basis. A source-set descriptor change requires reopening to capture a new admission. A native extractor must refuse or recapture if an undeclared external input would affect output; a path-neutral cached fact cannot carry path IDs or masquerade as a new revision.

The checkout worker watches creates, edits, removals and renames (both ends), debounces/coalesces events, and performs periodic full stat reconciliation. Overflow, watch failure, wake, bulk change and relevant config/ignore change require full reconciliation. If watching cannot work, expose degraded status and continue periodic full scans. Every full scan must re-enumerate sources and visited ignore rules and check even previously absent or unchanged-stat tracked config/manifest inputs; silently missed events must eventually be detectable. Watcher events are hints, not proof of a complete filesystem snapshot. Stat comparisons can avoid hashing unchanged sources, but racy timestamps, uncertain precision or clock behavior require conservative hashing. A preserved-mtime edit should be noticed by ctime where the platform supplies it. Unreadable or unstable required inputs cause failure, not a falsely complete publish.

Build evidence from captured bytes and recheck pending changes and root identity before publication. If a watched path changes mid-job, reread or promote to full reconciliation before committing; events after the final cutoff stay pending. Publish graph, source bytes, input inventory, dependency observations and generation/revision atomically. Search-only native card facts, card hashes and the head-only ranking FTS table join this same atomic publication; the background vector-cache job is not part of publication. Failed extraction, unstable inputs, cancellation or a failed commit leaves a compatible, validated prior head available for reads; an incompatible or invalid head stays unavailable until the worker rebuilds or reconciles it. Internal work/resource limits may yield explicit failure, never a silently truncated successful snapshot. No instantaneous freshness or guaranteed timer-to-publication deadline is promised.

<a id="semantic-evidence-after-the-syntax-tier-release"></a>
For native reassembly, retain dependencies for *measured* lookups, including unsuccessful and ambiguous lookups and traversed enclosing scopes, supertypes, imported modules and re-export sources. Diff old/new declaration surfaces, including headers, visibility, signatures, owners, imports, exports, supertypes and re-exports. Reassemble affected native call/declaration owners and reverse dependent admitted source sets in the same publication; unknown dependencies require wider, potentially whole-workspace reassembly. A body-only edit need not trigger unrelated surface dependents. No fixed fanout threshold is a topology contract. This work does **not** manufacture semantic target bindings: #22's producer owns `Reference`, `CallBinding`, `DeclarationBinding`, `Symbol` and `TypeRelationship` evidence. A newly added declaration cannot turn a historical unresolved semantic binding into a resolved one. Captured semantic artifacts remain historical; #22 decides their basis freshness and target checks. Semantic producer runs and the imports they generate are specified in [T09](#t09--semantic-producer-orchestration-21); the watcher never starts a producer.

## T06 — Rebuild and cleanup

A mismatched extractor/schema or invalid derived index must not be served or migrated. The daemon worker normally rebuilds index-owned content transactionally **in the existing index file**, with a new random generation and a reconciled full snapshot; requests and facts survive; retired records remain ignored. A failed rebuild does not serve invalid old state as a fallback. A compatible prior committed and validated head may remain readable during startup reconciliation, subject to root and selected-read checks; an incompatible or invalid one may not.

Only actual corruption or an index-file format failure preventing in-place replacement permits exceptional recreation. Ordinary busy, full-disk, permissions and I/O failures do not authorize deleting an index. Close old connections, take verified exclusive index use nonblocking, then recreate only index.db and its sidecars while retaining `requests.db`. If a reader holds shared use, defer recovery. No old and new file incarnations can coexist at the same pathname under live openers; partial recovery never signals success.

The daemon records last-opened time when it activates a checkout and may refresh it while active; reads do not write open-age metadata. Automatic GC eligibility is unchanged: a derived index directory qualifies when its recorded root is **missing or replaced**, or it has **not been opened for 30 days**. An index whose schema version predates the current one also qualifies, whatever its layout, root or age (Decision 0006 §2). The worker runs GC in maintenance units under verified exclusive index use, rechecks eligibility, and skips busy or unknown/unreadable entries. A daemon registry lookup alone does not protect live SQLite handles; index use locks remain until a proven replacement admission gate meets Decision 0008 §2. This is not a timer guarantee. Requests die with a deleted directory. A returning or replaced root starts fresh under its new captured identity, without reviving prior requests. Optional facts may be evicted without changing evidence. Optional vectors may be evicted without changing evidence; eviction can lower search vector completeness and change retrieval order, but does not invalidate a valid retained published matrix snapshot. `trellis gc --report` additionally reports `vectors.db` size and entry count without changing the cache or open age. Never automatically delete durable records, UUID markers, configured token/ledger trees or legacy state.

**Revision retention ([Decision 0006](semantic-evidence/decisions/0006-revision-retention-and-index-gc.md)).** Within a live index, the daemon worker retains the current head plus every revision superseded less than 15 minutes ago. It releases older revisions and collects unreferenced versions outside publication. Two holds, rooted at the head, outlast that grace (owner ruling 2026-11-01): the captured revision and the import revision of each batch the head selects. With P producer slots, a drained index keeps the head plus at most 2P full revisions; that doesn't grow with the number of imports, though tombstones and incidental raw batches mean disk use isn't literally constant. A pin to a released revision fails with a typed conflict and never moves to a newer revision, so old pins stop resolving past the grace. Readers write no retention state. Startup reconciliation, or an explicit request after its FIFO claim, whose capture shows no change takes the guarded unchanged path and publishes no new revision; the request completes `done` at the current head (Decision 0006, amended 2026-10-20).

`trellis gc --report` is read-only: show eligible, busy and unknown derived entries. Do not inspect retired saved records or update open age in report mode. `trellis forget` is removed; existing retired state stays ignored, not deleted.

**CLI usage.** Run `trellis gc --report` to print a read-only JSON inventory of derived indexes (eligible, busy or unknown); it does not delete anything or run automatic GC. The command needs no `--workspace` and does not inspect or move retired state.

**Producer state cleanup (#21).** The producer state directory (T02) is cleaned by phase, retained by count, swept after a crash and collected with its index.
- *Phase end.* When the producer exits, fails, times out or is cancelled, the owner kills its process group, waits up to ten seconds for it to empty, then removes `worktree/`, `bin/`, `home/`, `tmp/`, `target/`, `producer-config/` and `logs/`; the log tails are already in `run.json`. At the terminal transition it removes `out/` and `batch/`, which survive until the generated import request is terminal. A pickup directory is removed when its import request is terminal, or at once on a pre-import failure. When the wait for an accepted request ends early (`storage_busy` after the bounded wait; on a closing runtime the owner is normally closed first, so nothing is recorded) the directory stays, because the request still reads it, and the next activation sweep removes it once no queued or running request names it. The pickup records that attempt as a transient failure carrying the request ID. Before any later automatic import it reads that request's row under the pickup workflow: a `done` row is recorded as done, a `failed` row is recorded with its typed code and judged by that class, a queued or running row starts no new import and the automatic import fails with `producer_busy` (an unjudged hold: nothing is written to `lastImported`, so the watcher keeps re-reading the artifact and imports changed bytes once the request settles), and an unreadable row imports nothing. Only a row that no longer exists, or a transient failed row, is retried after the retry interval, so contention never produces a second request for the same bytes.
- *Retention.* `run.json` is kept for the 10 newest terminal runs per root key; older run directories are deleted at each terminal transition and in the sweep. A run directory that a queued or running generated import request names is never deleted by retention and does not count toward the 10: the pending-input lifetime above wins over retention (and over the T02 disposable ruling), and the directory is retained by count again once that request is terminal. When the pending set cannot be read, retention waits for the next sweep. Pickup directories never consume run retention.
- *Sweep.* The daemon sweeps in activation, after the staging sweep and before the first FIFO claim, and again before each new run. A non-terminal run owned by another daemon (PID and start time) is marked `failed/abandoned` and stripped to `run.json`, keeping `out/` and `batch/` only while a queued or running generated request names the directory (T04 reclaim); a later sweep strips them once that request is no longer pending. Its process group is sent SIGKILL only when the recorded group leader is alive and its start time equals the recorded value; a process whose start time differs is never signalled. Every pickup directory that no request names is removed. A `run.json` or `pickup.json` that fails its closed parse is `producer_state_corrupt`: the run record is ignored and its run directory swept, or pickup is disabled with that status. A run record that cannot be read for another reason (an I/O error) is left in place and reported by the sweep. Records are not signed or re-validated (T00).
- *GC.* Removing a derived index removes `<cache>/producers/<root-key>` under the candidate's exclusive use lock, after the index directory and before the lock file. Producer state that is not a private directory makes the candidate skip. A removal failure is past the unlink boundary and is returned as an error; the lock stays. *Orphan rule:* a `<cache>/producers/<key>` entry (64 lowercase hex, not the current key) whose `<cache>/indexes/<key>` does not exist is removed under that key's exclusive use lock (created when absent), and the lock is removed. Orphans are not counted as removed indexes, unsafe orphans are never repaired, and when `<cache>/indexes/` is absent orphans are left. GC of a checkout's index also drops its `pickup.json`.
- *Disk use.* Disk use inside a run directory while the producer runs is not bounded: `target/`, `home/` (trusted Gradle or Maven downloads), `tmp/` and the worktree can grow. A full disk is an ordinary fault reported as `producer_failed` with diagnostics. Everything except `run.json` is removed when the phase ends. A descendant that calls `setsid` or `setpgid` leaves the process group and is not tracked.

Semantic batch-import staging (`<index-dir>/semantic-stage-<requestId>-<claimIncarnation>/`) is disposable derived state private to the claiming worker's operation (#61, owner ruling 2026-10-26). It is never read by public readers and is never authoritative queue state. Its operation removes it on every exit; the worker's startup sweep removes any residue before the first FIFO claim. While residue exists, whole-index GC skips that directory as an unknown entry.

## T07 — Ownership and limits

[#22’s stable identifiers](semantic-evidence/contract-v1.md#stable-identifiers), [durable anchors](semantic-evidence/contract-v1.md#durable-anchors), and [basis/freshness](semantic-evidence/contract-v1.md#basis-and-freshness) govern IDs, attachment, pins and evidence interpretation. This topology’s root key, UUID and index generation/revision serve placement and snapshot coordination, not competing semantic algorithms; the former per-checkout leader incarnation is not a read gate. [#24's MCP contract](mcp-readonly-pilot-contract.md) defines wire requests, result basis and pin shape. The MCP tool catalog and its order are defined by #24. It specifies eleven read-only tools, including `trellis_search_symbols`; search’s allowed local query embedding does not alter the cached-only code-evidence rule. Declaration has no `limit` or `view` input; outgoing calls has optional `limit` and no `view`. Find, declaration and outgoing data use compact `doc` references into per-result `documents` tables, and their symbol, declaration and call ranges include inclusive 1-based `lines` when source is selectable. Source reads can use the referenced path and `contentHash`, those lines and the same `expectedBasis`, subject to source caps. Each tool returns a deterministic `content[0].text` summary of at most 512 UTF-8 bytes and full schema-valid `structuredContent`. Eligible evidence reads each use one selected committed snapshot, not live source; describe may instead report not-ready status with a null basis. Source reads verify the selected raw cached BLOB’s path/version identity and whole BLOB hash/length before slicing; they decode only requested LF-delimited bytes. Other selected readers, including public `source_at`, trust the published native, graph and class rows without re-attesting them against source (owner ruling 2026-10-23, #261); a stored row that does not decode, or a source BLOB whose length or hash disagrees, is corruption and schedules a re-index. The narrow optional vector-row decode-miss exception is defined in T00/T02; it does not change required index-row or source corruption rules. No legacy state or saved view/note migration is implied; the removed `--state-dir` option and old path-bound DBs carry no compatibility promise. Move existing in-tree token files manually to configured external paths with Trellis stopped. Retired ledgers stay ignored; there is no report, migration or deletion path for them.

The boundary is the OS user, not an agent principal. stdio opens no network listener and grants its configured agent access to the selected checkout, without per-path grants; source text is data, never instructions. The daemon selects and checks the checkout/root for each call; an admitted evidence read retains one eligible cached snapshot through response finish, and the selected root is rechecked before sending. A verified prior head may answer with `catchingUp:true` while reconciliation or queued work is pending; this is not a live-disk freshness guarantee. Per-call limits do not cap many same-user processes in aggregate. Unsupported local locking refuses topology use; network/distributed filesystems and hostile same-user mutation fall outside this safety claim.

**Semantic batch import memory (owner ruling 2026-10-30, #394).** One batch import's live memory budget (`unit_expansion_bytes`) is 1 GiB; it was 128 MiB under #410, and the other #410 caps are unchanged. The decoder's per-document reservation and the staged join's live reservations both draw on it. A live reservation counts the Rust heap bytes the import requests (layout sizes) and is admitted before the allocation it stands for; SQLite page caches (`cache_bytes`), tree-sitter's C memory and allocator slack are outside it. A long-lived owner is charged at its retained storage, measured from real capacities once its build ends, not at its build's peak; a shared-pin settlement reads the captured join's rows instead of copying them. Exceeding the budget fails the batch typed, `limit_exceeded: unit expansion`. With `TRELLIS_INDEX_DIAGNOSTICS=1`, the `semantic-join-ledger` line reports the join's peak as `liveHighWaterBytes`.

## T08 — Worked checks for Stages 2–4

The labels here are fixture placeholders, **not #22 identity vectors**. For each case, verify the reported result and the unchanged or changed protected state; the document itself adds no tests or production code.

1. **Selection and identity (AC1).** Implicit `/repo/sub` finds `/repo/.git`; explicit `/repo/sub` without its own marker uses path identity. A valid `.git` pointer to a private linked-worktree Git directory gets that directory's UUID. Malformed pointers, symlink targets and invalid UUIDs refuse without searching upward or replacing bytes. Two creators converge on one marker; if either crashes before fsync, a valid-marker adopter completes marker/directory/parent fsync before acknowledging the UUID. Moving a Git checkout preserves its UUID; no retired record database is opened or created.
2. **Use locks and daemon restart (AC2).** Reader holds shared index use; GC/recreation cannot get exclusive use and leaves files untouched. After deletion, a waiter on the old lock inode detects the changed pathname and retries. If the daemon crashes at generation G1, a new daemon instance opens the queue and confirms old-root settlement, then runs startup reconciliation before FIFO claims. While reconciliation runs, a compatible committed, validated G1 head may still answer root-checked reads with `catchingUp:true`; if there is no valid published head, evidence returns `index_not_ready`. Neither a missing per-checkout lock holder nor a new daemon instance alone makes a validated head ineligible.
3. **Ordered updates and root identity (AC3).** Browser request Q1 and CLI request Q2 queue while a watcher edit is pending; one checkout worker publishes serially, and every result uses one coherent revision. A crash after Q1's index publish but before its completion permits repeat work without regression; Q2 remains accepted across index rebuild. Move the root or replace its inode: old openers refuse evidence and waiting clients report `root_changed`. The old runtime or a fresh replacement runtime settles old-root queued/running rows before any replacement work; without either opener, GC may discard the abandoned requests. Replacement enters through fresh reconciliation, never through old requests; failed recording cannot be reported as success. Overflow or a lost watcher event forces full scan; a silently changed tracked config is found by the next successful full scan.
4. **Reassembly and recovery (AC4).** Add a declaration named by an unresolved native lookup: reassemble affected native owners and dependents atomically, including previously unsuccessful lookups, but leave historical semantic `CallBinding` unresolved. Remove a supertype/import and reassemble its dependents. A failed publish leaves earlier graph, dependencies and source bytes together. An incompatible index rebuilds in place with new generation G2 while accepted requests survive and retired records remain ignored. Corruption requiring recreation waits for all shared-use readers and preserves requests; busy/full-disk alone never triggers recreation.
5. **Retired state and cleanup boundary (AC5).** Existing saved record databases, sidecars, locks and configured Jev/ACP trees remain unaccessed and unchanged during normal startup, reads, indexing and `gc --report`. GC skips an open index and may remove a missing/replaced root or a 30-day unopened derived index under exclusive use; it cannot remove retired state. A read writes no last-opened metadata. `gc --report` changes no files and does not enumerate saved records. `forget` is an unknown command.

## T09 — Semantic producer orchestration (#21)

`trellis producer plan|run|cancel|status|pickup` run or import headless semantic producers for one checkout. The first four are owner commands; nothing in the watcher, the MCP server, the browser server or daemon launch reaches a producer. `plan` and `status` read and hash files and the retained revision only. `run` recomputes the plan and refuses with `plan_changed` unless its `planSha256` equals `--plan-sha256`.

**Trust profiles.** `--trust restricted` (the default) runs no repository code; `--trust trusted` allows the producer to run repository build logic. `rust-analyzer` has no restricted row (`profile_unsupported`): it cannot disable build scripts or proc macros. Policy decisions report an enforcement kind, `structural`, `producerFlag`, `advisory` or `notEnforced`. Structural means Trellis provides nothing the action needs; no policy claims filesystem or network isolation, and a descendant that leaves the process group is not tracked.

**Controlled worktree.** A run generates in its private run directory (T02), never in the workspace. The producer's working directory is `<run>/worktree/`, written once per file from one retained native revision: every document, then the present entries of the retained config component, then those of the dependency component, minus the profile's omissions plus its generated files. The live workspace is never read, so a run has one basis, and the indexed workspace is not modified.

**Environment.** The child environment is an allow-list built in one place: `HOME=<run>/home`, `TMPDIR=<run>/tmp`, `LANG`, a `PATH` set per profile row, and only the declared cache variables a row names. The caller's environment is used for resolving executables and cache locations, never inherited. Credential and injection variables (`NODE_OPTIONS`, `JAVA_TOOL_OPTIONS`, `RUSTC_WRAPPER`, `PYTHONPATH`, `LD_PRELOAD`, `DYLD_*`, `*_TOKEN`, `AWS_*`, proxies, `TRELLIS_*`) are absent.

**Bounds.** The run owner samples every 500 ms. The wall-clock bound (`--timeout-secs`, 1 to 14400, default 1800) ends the run `timed_out`. The resident-set bound (`--memory-mib`, 64 to 65536, default 8192) is sampled over the whole group and reported `enforcement: sampled`; there is no address-space limit, and a spike between samples can exceed it. The artifact is bounded at 256 MiB, and each log stream at 4 MiB on disk with the last 16 KiB kept in `run.json`. Every ending sends SIGTERM to the group, waits two seconds, sends SIGKILL, and waits up to ten seconds for the group to empty; `groupSurvived` reports a member that did not leave.

**Cancel.** `producer cancel --run <id>` is honored during `materializing`, `running` and `writingBatch`, terminates the group and ends the run `cancelled`. After the import request is enqueued it answers `not_cancellable: import accepted as request <id>` (T04).

**Run record and reply.** The owner alone writes `<run>/run.json` atomically at every transition. The reply is `{runId, state, outcome, errorCode, planSha256, producer, trustProfile, sourceRevision, import, diagnostics}`. `outcome` is one of `imported`, `producer_failed`, `timed_out`, `cancelled`, `limit_exceeded`, `producer_output_missing`, `producer_output_invalid`, `stale_basis`, `import_failed`, `root_changed` or `abandoned`. Diagnostics carry the exit code or signal, the duration, the peak resident set, the artifact and stream sizes and the stream tails. `producer status` reports `activeRun`, each producer's `mode` (`restricted` or `trusted` when its newest run, active or finished, imported under that profile, otherwise `importedOnly`) and `lastRun`, and `--run <id>` adds that run's record. The command prints the reply and exits non-zero unless `state` is `done`; a failed import carries its typed code (T04). Once the import is enqueued, `out/` and `batch/` stay until the request is terminal. If the run can no longer observe the request (the queue stays busy past a bounded wait, or the runtime closes while it is queued), the command fails with `storage_busy` or `root_changed`, and the record stays `importing` with its request ID.

**Strict basis rule.** After the producer exits, the head's native revision must equal the plan's `sourceRevision`, else the run is `stale_basis` and submits nothing. The batch is written in the same read, so its descriptor binds that revision. The import worker repeats the check against the head just before publication, on every revision-conflict retry, and a mismatch is terminal `stale_basis: head revision changed`. There is no per-document diff: any change to the head's revision rejects the run's result.

**Crash recovery.** A daemon that crashed mid-run leaves a non-terminal `run.json`. The next activation sweeps it (T06): the recorded process group is killed only when its leader still has the recorded start time, the run is marked `failed/abandoned`, and its directory is stripped to `run.json` unless a queued or running generated import still names it. The sweep also runs before every new run, where it leaves pickup directories alone because this daemon may be importing one.

**Limits.** A trusted profile's builds are not sandboxed. A run whose artifact `project_root` is neither empty nor one of the two spellings of its worktree fails as `producer_output_invalid: project root`. Real producers cannot run in restricted mode where they need network or interpreter access Trellis withholds, and then fail with their stderr tail in the diagnostics.

### Pickup

`trellis producer pickup --producer <name> --artifact <abs path>` configures one artifact per producer in `pickup.json` and imports it at once, as an explicit owner action, replying with the typed import outcome. `--clear` removes the entry. The path must be absolute, UTF-8, at most 4096 bytes, have an existing parent directory and lie outside `<cache>` and `<data>`. Pickup never runs a producer: `pickup.rs` and `pickup_watch.rs` reach only the state, batch, import, pickup and pickup_watch modules, and a static check and the runtime tripwire proof enforce it.

**Triggers.** Each checkout's pickup owner arms a non-recursive `notify` watcher on the artifact's parent directory, filtered to its file name. An event starts a 2 s debounce, after which the file's `(len, mtime, inode)` must stay unchanged for 1 s before an import is attempted. One check runs after startup reconciliation (the activation check), so a sweep of pickup directories cannot race an import. A stat check every 60 s re-reads the artifact only when its stat changed; otherwise it asks only whether the last outcome is due again: a failed one by the decision table, a `done` one when the head no longer selects its evidence (an index rebuild or a live corruption recovery dropped it, with no artifact change). Watcher events are hints and the 60 s check is the liveness backstop (T05). `producer status` reports `pickup.watch` as `active` while the watcher is armed, or `degraded` when it could not be armed (for example the directory is missing) or the pickup configuration cannot be read; a degraded pickup is still covered by the 60 s check, which also re-reads the configuration and re-arms the watcher. The owner stops with the runtime, and `--clear` stops the watch. In a test-support build, `TRELLIS_TEST_PICKUP_INTERVALS` (a JSON object with `debounceMs`, `stableMs`, `checkMs` and `retryMs`) overrides the intervals.

**Decision table.** An automatic trigger hashes the artifact and decides from the last outcome recorded for the same `sha256`:

| Last outcome for the same `sha256` | Action |
|---|---|
| none, or a different `sha256` | import |
| `done`, and the head still selects a batch of this producer that captured these bytes | skip |
| `done`, but the head no longer selects such a batch (an index rebuild dropped it) | import |
| failed with class `invalid_artifact`, `invalid_request`, `limit_exceeded` or `producer_output_invalid` | skip while the head revision equals the recorded `sourceRevision`; import once the head changes |
| failed with any other class (`stale_basis`, `revision_conflict`, `capture_unavailable`, `root_changed`, `index_failed`, local I/O) | import once 60 s have passed since the attempt |

A transient retry therefore happens at most once per 60 s and a deterministic retry at most once per head change. A skip writes no batch. The explicit `--artifact` command ignores the table.

**Unchanged bytes.** When the head already selects a batch of this producer that captured the same artifact bytes at the head's native revision, an import (explicit or automatic) submits nothing and writes no batch: the reply is `state: done` with `unchanged: true`, the head's `publishedRevision` and the selected batch's report, and `lastImported` records `done` (an earlier `done` for the same bytes and revision is kept, request ID included). A new attempt's `generationId` would otherwise make an otherwise identical descriptor differ, which the store refuses for bytes it already captured.

## #64 one-capture admission boundary (intermediate, not a rebuild lifecycle)

The indexer admits the root, visited directories, supported source paths, 22 root
project inputs, two root Rust toolchain selectors, and present or absent `.gitignore`
and `.ignore` files in visited directories. It reads each admitted source through one
no-follow regular-file descriptor and shares that immutable buffer with the current
graph extractor. It also captures the running native executable and optional display
artifacts. Metadata and complete eligible source/directory inventories are checked
again at cutoff. Source-identity aliases (including lexical `./` paths and hard links)
used as display inputs refuse admission before the optional read; nonregular eligible
sources such as FIFOs refuse admission rather than disappear from the inventory.
Identity-equivalent non-source inputs reuse one captured buffer after metadata checks.
Drift, unreadable or unsafe inputs, excess size, and cancellation
fail the indexing call rather than publishing its result. Ambient ancestor, global,
and Git-info ignore files do not participate in admission.

This is a non-adversarial writer check, not a filesystem security sandbox. A writer
able to restore *all* observable identity, size, mtime, and ctime metadata between
checks can evade it. Ancestor directory replacement is not capability-fenced.
The original #64/#70 one-shot capture and publication work preceded the
daemon-owned `requests.db` queue, incremental indexing and watcher. T03–T06
and Decisions 0008/0009 govern their implemented ownership and recovery now.
