# Decision 0019: Rust expression macros are measured as expressions

- **Status:** owner ruling, 2026-10-31, on [#519](https://github.com/SquashMerge/trellis/issues/519): "expand into macros. Recovering macro call sites is a main reason for SCIP."
- **Amends:** [contract-v1](../contract-v1.md) #279 amendments (production measurement capabilities, and native identifier-site candidates): the opaque Rust macro rule now has an allowlist. [Decision 0003](0003-per-document-occurrence-ids.md) ordering gains one tie rule (below); its identity inputs are unchanged.
- **Scope:** native producer `trellis.native.syntax@native-v12` and index schema 32. Indexes are disposable and are rebuilt, not migrated.
- **Evidence:** `trellis-evidence/rust-scip-partial/REPORT.md` (2026-10-31). Native-v11 skipped every Rust `macro_invocation`, `token_tree` and attribute span. On this repository that hid 4,895 internal call sites (17.5%), and it was the only reason 243 of 257 rust-analyzer SCIP documents were `partial`. A SCIP call binding needs a native call site (contract §166), so rust-analyzer could not add those calls either.

## Decision

1. **Allowlist.** The native producer measures the token tree of these Rust macros as Rust expressions: `assert`, `assert_eq`, `assert_ne`, `debug_assert`, `debug_assert_eq`, `debug_assert_ne`, `ensure`, `bail`, `anyhow`, `format`, `format_args`, `write`, `writeln`, `print`, `println`, `eprint`, `eprintln`, `panic`, `unreachable`, `todo`, `vec` and `dbg`. The macro path is a bare name or a `std::`, `core::` or `alloc::` path (`anyhow::` for `ensure`, `bail` and `anyhow`), matched by parsed path segments so whitespace and comments between segments do not matter, with any delimiter.
2. **Parsing.** The token tree is re-parsed as one comma-separated argument list (`vec!` as an array expression, including `[x; n]`), at the token tree's exact byte offsets in the original document. The parse reads only the token tree's own bytes. A fixed wrapper supplies the expression context: it is laid over offsets before the token tree and one byte after it, so every parsed node keeps its document byte range. A tree with any parse error or missing node stays opaque, with no partial guessing.
3. **Measurement.** Inside a measured macro, calls, control regions, references and declarations (closures) are measured with the ordinary rules, at ordinary spans and with ordinary owners and regions. The macro path is ordinary path syntax and yields ordinary reference candidates.
4. **Format strings stay opaque.** The format string (the first argument of `format`-like macros, the second of `write`, `writeln`, `assert`, `debug_assert` and `ensure`, the third of `assert_eq`-like macros) is never measured. It is a gap when it names an argument: an implicit `{name}` capture, a `{name}` named argument, or a `name$` width or precision; a non-raw literal is judged by its decoded value, so an escaped brace such as `\u{07b}` counts, and an escape that does not decode keeps the literal opaque. The name of a `name = value` argument after the format string is a gap too; its value is an expression.
5. **What stays opaque.** Every other macro, including `json!`, `matches!`, `select!`, `params!`, user and unknown macros, `macro_rules!` bodies, attributes, and any allowlisted macro whose token tree does not parse cleanly or does not fit the bounds below. Each is a whole-invocation gap, exactly as before. A nested opaque macro inside a measured one is its own gap.
6. **Gaps narrow to what remains.** A measured macro has no gap of its own. Its residual gaps are its opaque format strings, named-argument names and nested opaque macros or attributes.
7. **Bounds.** Expansion never makes a document fail. Each re-parse is charged to a per-document byte budget (eight times the document length plus 64 KiB). Before measuring, the expansion's whole subtree is reserved against the walk's existing visit (1,000,000) and depth (128) bounds; a macro that would cross a bound stays opaque. Nested macros are measured inline and checked the same way, and a nested reservation also leaves room for the rest of its enclosing expansion.
8. **Identity stays stable outside macros.** Allowlisted macros are measured after the document's ordinary walk. Within each owner and kind, facts inside an outermost measured macro take their ordinals after all the owner's other facts, each group in `(start,end)` order, and a closure inside one takes its sibling ordinal after its ordinary siblings. So, under one native producer version and extraction context, every declaration, call, control region and reference outside the measured macros has the same syntax ID, occurrence ID, owner and ordinal with or without expansion. The capability report records the outermost measured macro invocation spans as `macroExpansions` (sorted, disjoint, Rust only, omitted when empty), and the validator orders facts by `(insideMacroExpansion, start, end)`.
9. **Joins.** No join rule changes. SCIP occurrences at newly measured spans join as usual; occurrences still inside a gap stay `unsupported`, and a document's semantic coverage becomes `complete` when no unsupported occurrence remains.

## Consequences

- The native producer version is `native-v12` and the index schema is 32 (new `native_version_macro_expansions` rows). Older indexes are recreated, not migrated.
- Rust attributes (`#[derive]`, `#[test]`, `#[serde]`) remain opaque, so a document with attributes stays natively `partial`, and rust-analyzer occurrences inside them stay `unsupported`.
- The sequence (behavior) view still treats every macro as a boundary; only native measurement, and the graph rows and semantic joins derived from it, change.
- The JavaScript semantic-contract reference checker and the test-support `native-capture` export do not carry `macroExpansions`. No conformance corpus has Rust macros yet; a Rust corpus must add both.
