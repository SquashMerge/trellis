# Decision 0015: hash-based identity for native syntax and occurrence IDs

- **Status:** owner-approved amendment (2026-10-21, [#199 owner ruling](https://github.com/SquashMerge/trellis/issues/199#issuecomment-6327095503)).
- **Scope:** only the existing native `sid:v1:` and `occ:v2:` ID namespaces and their collision handling in [contract v1](../contract-v1.md#stable-identifiers). This narrowly amends [Decision 0001](0001-core-contract-v1.md)'s unconditional distinct-canonical-input collision rule and qualifies [Decision 0003](0003-per-document-occurrence-ids.md)'s unchanged-collision statement. It does not extend [Decision 0010](0010-native-revision-identity-over-content-hashes.md)'s revision-ID-only scope.

## Owner ruling and reason

The owner accepts the residual risk of different canonical inputs sharing a full SHA-256 digest, calling that risk “practically zero” in the linked ruling. The [#199 owner ruling](https://github.com/SquashMerge/trellis/issues/199#issuecomment-6327095503) explicitly calls this **hash-based identity**, acknowledges the residual full-digest collision risk, and requires an amendment before relying on it. Full-digest equality is an operational identity rule, not a mathematical proof that canonical bytes are equal.

## Amendment

For both native ID kinds, hash the **validated canonical input** once with its unchanged NUL-terminated domain (`trellis.syntax.v1\0` or `trellis.occurrence.v2\0`). In the producer's retained identity domain, the resident registry key is `(ID namespace, first 16 digest bytes)` and the value is the **binary 32-byte full SHA-256 digest**. The namespaces remain distinct even when their 16 digest bytes match. A repeated key with an equal full digest is treated as the same identity and needs no second append to the document-local first-insertion list; canonical input bytes need not be retained or compared. A repeated key with a *different* full digest is a detected 128-bit-handle collision: reject the affected artifact atomically, without aliasing, an ad hoc suffix or a different ID length.

A collision in all 256 bits between different canonical inputs is not detectable by this digest-only comparison and could alias; the owner accepts this nonzero risk. The former unconditional promise to detect every distinct-canonical-input collision on the emitted 128-bit handle in Decision 0001 and contract v1 is replaced **only** for these two native ID kinds by this full-digest comparison. Decision 0003's collision-handling statement follows this amendment. Canonical input encoding and domains, emitted lowercase IDs and full-hex integrity hashes, published vectors, duplicate-record rejection, authenticated extraction context, revision-scoped semantic validity, proof joins, selected-document read attestation, source and projection witnesses, and atomic publication safeguards remain unchanged. This decision imposes no new size cap, identity fallback, or hardening requirement.
