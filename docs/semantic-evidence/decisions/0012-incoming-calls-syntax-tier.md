# Decision 0012: name-matched incoming calls syntax tier

- **Status:** owner-ratified 2026-10-17 (#172), after #168 merged. This records the existing ruling, not a new approval or product gate.
- **Amends:** #59's incoming-calls contract only for this syntax tier and `../../mcp-readonly-pilot-contract.md` (#24). See [Decision 0011](0011-test-production-declaration-role.md) for the stored declaration role.
- **Compatibility:** none needed for disposable derived indexes. Change the native producer version and rebuild the index; do not migrate it.

## Decision

1. Add the standalone read-only MCP tool `trellis_incoming_calls` now. Its closed syntax-tier input is `{schemaVersion:1,workspace?,symbolId,limit?,expectedBasis?}`; there is no `view` or semantic-producer selector. Name matching is the **narrow exception** to #59's “not a name/spelling search” requirement. The exception never claims an exact target, graph edge, all callers or reverse-call completeness. #59's exact semantic tier retains its admitted bindings, dispatch and selected-producer evidence requirements and its #40, #41 and #58 prerequisites.
2. `NameMatch` has fixed basis `"name"`, the count of eligible same-name declarations (including the selected declaration) and the fixed limitations `aliases`, `functionValues`, `reExports`, `dynamicDispatch`, `opaqueMacros`, `sameNameDeclarations`. Each incoming item is a measured call site with fixed `matchedBy:"name"`, null binding and target, unresolved disposition, missing-evidence boundary and fresh syntax evidence. This name relation has no borrowed producer proof. An empty list must retain the match basis, searched `scopeCoverage` and limitations, and must not assert that no callers exist. Warnings use only #22 warnings-v1 codes.
3. Admit a call only when its full measured spelling and callee range prove one language-decoded identifier token and its lookup key equals the selected declaration's key in the same eligible snapshot, language and source set. A verified member-name token qualifies. Under the owner ruling of 2026-10-23 ([#194 item 3, option (a)](https://github.com/SquashMerge/trellis/issues/194#issuecomment-6375543246)), a Rust `scoped_identifier` callee also qualifies through its parser `name` field **only** when that final segment is a lone `identifier`; unwrap a parser-recognized `generic_function` through its `function` field first. This admits `Self::foo()`, `module::foo()`, `Type::foo()`, `Type::<T>::foo()` and `Type::foo::<T>()` when the measured callee range/spelling are exactly `foo`. It is name matching, not path resolution or suffix splitting. A non-identifier final segment and an unverified compound expression yield no token or guessed match. Test those path forms and a parser-proved non-identifier negative. This changes native measured fields and therefore requires the native-v9 producer version; it adds no limitation or new MCP field. Keep #22's authored `Call`, exact semantic binding and dispatch prerequisites unchanged. Compute the derived native-call `callee_lookup_key` when publishing verified captured bytes, index `(source_set,language,callee_lookup_key)`, and rebuild the disposable index on producer/schema change.
4. Include recursion. Sort by stored `callerRole` (production before test), then #167 proximity to the selected declaration (same document, same directory, elsewhere), then `(path,range.start,range.end,callId)`. Role is Decision 0011's producer-classified declaration role, never inferred from a path during the read. The result carries the selected declaration and emitted calls' required evidence closure and four-row searched-scope coverage. Only selected source-set/language native tuples count toward that scope; an incomplete selected scope cannot support a negative claim. Limit 20 by default, accept 1–50, and apply the 65,536-byte full-response cap and five-second deadline. A required caller removed by limit reports `limit`; one removed for bytes reports `response_bytes`, with required closure retained for every emitted item.
5. #59's later semantic tier amends **this same tool** and its closed input/output schemas with semantic-producer selection, typed binding and target, and semantic match basis. Those fields are not reserved by the syntax tier. #60's other five relations (`call_paths`, `usages`, `type_hierarchy`, `implementations`, `coverage`) stay behind their existing prerequisites; when scheduled, each is a separate tool, not an `inspect` view (#160). No other #60 behavior changes. The original five-tool W10 closed-view rejection remains historical and still applies to its `view` inputs; the standalone sixth tool is not such a view.

[#172](https://github.com/SquashMerge/trellis/issues/172) is the ratified product ruling. #24 below specifies the closed wire projection. #59 and #60 issue-body amendments are separate follow-up edits after reviewed documentation merges; the superseded historical pilot implementation plan is not rewritten.
