# Decision 0005: same-generation executable drift (PR #98 owner ruling)

**Status:** owner-ratified PR repair for schema 8 / current native extractor.

`native_producers.executable_hash` is the immutable **generation-origin** descriptor, not a gate against an ordinary executable rebuild. A new executable hash keeps the generation, old pins and `requests.db`. It requires FULL fresh capture, measurement, extraction and validation. New revisions retain their own executable Present SHA and an additive per-revision binding over canonical persisted selector observations, executing producer identity and revision-header hashes. Selected new-pin reads recompute the binding and refuse missing or mismatched fields. Existing validated pins remain readable under their original T00 trust-as-written publication boundary.

Decision 0003 still governs identity: executable SHA belongs to revision provenance, not `extractionContext`, `occ:v2`, `document:v1` or native producer version. Fully remeasured facts matching an existing per-document normalized witness may attach that immutable version under new revision provenance. Different measured facts for equal content/context/producer version **must fail** with an actionable producer-version-bump error and no publication. Real schema/extractor mismatch continues through the separate obsolete-marker ruling; ordinary binary drift does not recreate or rotate the index.

**T00 limit:** The new binding is an *unkeyed persisted consistency check*. It detects missing and unilateral/corrupt fields. It is not an external MAC and does not resist a coordinated same-user rewrite of inputs, binding and header. Never call it tamper-proof. Selected source/native/graph/class row attestation and ordinary SQLite corruption refusal remain required.

## Amendment: fresh-build validation (#199 I-4b, #223, owner rulings 2026-10-19 and #225 2026-10-24)

"Validation" of a fresh full build means every structural check of the artifact against its capture, the capture freshness checks and every bundle check at publication. Neither this process's own fresh build nor a plain `Artifact` handed to the store (`Store::publish_native`, the recreate stage) is rebuilt a second time and compared. `Artifact::validate` checks the captured header and runs one `validate_structure`, with capture freshness and cancellation checks before and after. The #225 owner ruling of 2026-10-24 supersedes the earlier plain-`Artifact` rebuild-and-comparison requirement. `build_native` determinism is checked instead by the verify test `native_build_is_deterministic`, which builds the same capture twice and requires byte-identical artifacts.

## Amendment: build-time extractor producer hash (owner-approved 2026-10-19, #199 R-1/R-2)

This amends the "FULL fresh capture, measurement, extraction and validation" requirement above. The rest of this decision, the fresh-build validation amendment above, Decision 0003 and T00 still hold.

- **The producer hash.** `build.rs` computes a build-time hash of the native extraction inputs and compiles it into the executable. It covers the exact bytes of an explicit list of extraction modules plus the `Cargo.lock` name, version and checksum of the extraction crates. Both lists live in `build/extractor_inputs.rs`.
  - **Modules:** `native_evidence`, `native_ids`, `indexer`, `indexer_java`, `indexer_python`, `indexer_rust` and `classes` (the ruled list). Two additions: `model`, whose graph types' serde shape is the stored graph payload and projection-hash input, and `parallel`, whose ordering contract keeps extraction output byte-identical to a sequential run.
  - **Crates:** every `tree-sitter*` package (runtime and grammars), `icu_normalizer` and `icu_normalizer_data` (lookup-key normalization), `serde_json` (payload and canonical bytes) and `protobuf`/`scip` (SCIP presentation labels in graph projection).
  - The `test-support` feature flag is hashed as well.
  - The hash is never maintained by hand. It is not `nativeProducerVersion`, and it does not enter `extractionContext`, `occ:v2`, `document:v1` or any other ID.
- **The guard.** Verify tests (`src/extractor_inputs_tests.rs`) fail when:
  - the built hash differs from one recomputed over the listed inputs;
  - a listed module uses a crate module that is neither listed nor an explicitly named non-extraction item;
  - a module outside the list parses source and is not a declared read-time view.
- **Where it is recorded.** Each new revision records the executing hash as the persisted capture input `extractor:trellis.native.syntax`. The executable observation and its SHA binding are recorded as before.
- **Reuse under a rebuilt executable.** A new executable hash keeps the generation, old pins and `requests.db`, as before. The capture is always fresh and fully hashed. Native facts are then decided by the producer hash, not by the executable hash:
  - **Equal recorded hash:** the selected head's validated facts and projections stay valid, exactly as for an unchanged executable. An unchanged capture publishes one metadata-only revision: the selected manifest under a fresh revision header (the toolchain hash and native revision ID carry the new executable SHA), fresh capture inputs and a new producer binding, so the head names the executing executable. (Under the same executable an unchanged capture publishes nothing; Decision 0006 §3.) Changed captures follow the local-publication amendment below.
  - **Different or unrecorded hash:** FULL measurement, extraction and validation, as before (validation as the fresh-build amendment above defines it). Fully remeasured facts that match an existing per-document witness may attach that version. Different measured facts for equal content, context and producer version still fail with `native_producer_version_required`.
- **R-1: publication reuse trusts stored IDs (#225 owner ruling, 2026-10-24).** When there is no producer drift and all three freshly computed document-version, graph-projection and class-projection IDs match the selected head, publication attaches the prior rows by ID without repeating native-witness or projection verification. Partial-family reuse retains its existing stored-hash checks. Under producer drift, the per-document `native_witness` comparison and actionable producer-version-bump failure remain required by this decision. Selected-document read attestation is unchanged.
- **T00 limit.** The recorded hash is an unkeyed record of what Trellis wrote. It detects missing records and accidental mismatches, not a coordinated same-user rewrite.

## Amendment: N-document local publication (#225 owner rulings, 2026-10-21 and 2026-10-24)

With unchanged native extraction, admission and presentation inputs, any number of source changes takes the local path, regardless of edit shape or parser coverage. Inventory changes are included: additions, deletions and renames (delete plus add). Only added or changed current documents are extracted; deleted documents leave the selected manifest. Unchanged native and graph rows are reused by ID. The complete class catalog is logically recomposed from cached unchanged file extractions and fresh changed file extractions. As Decision 0004 permits, compact summaries may prove that every global budget fits; unchanged complete class projections then reuse their selected IDs directly, while changed files and previously incomplete selections supply their per-file rows. Class projections of unchanged documents are refreshed when catalog caps move. If a global cap may be reached, the first #300 implementation retains full composition from the stored and fresh extractions. Summaries, diagnostics, coverage and all published content must match a full rebuild of the same capture. Capture freshness, expected-head checks, atomic publication, retained-pin behavior and producer-drift checks remain required.

## Measurement evidence: watcher or request publication (#225 owner ruling, 2026-10-24)

Each single-file performance sample runs from immediately before the edit until the indexing CLI returns. The returned revision must contain that edit's exact bytes. Its actual publishing path must be LOCAL, whether the watcher or the explicit request published it; diagnostics bind the publisher, mode and writer counters to that revision. Each sample records which one published it. A missing, ambiguous or non-local publication fails the sample. No sample is discarded or retried. This includes watcher debounce and the complete CLI wait. The existing 20 samples per edit shape, separate p95 thresholds, fact floors and independent full-rebuild parity checks are unchanged.

## Native-v9 integration (#225 owner ruling, 2026-10-24)

The #225 branch integrates #299's native-v9 contract and #302's reference-storage changes in disposable index schema 20. References, capability families and measurement gaps belong to the immutable native document family: reuse by ID retains them, changed-document extraction publishes them, and retained/semantic reconstruction preserves their report revision scope. Local publication and full-rebuild parity include all three v9 table families. Matched v8/v9 measurements run on the combined head after #225 merges (owner ruling, 2026-10-25), not the earlier native-v8 baseline; adding reference rows does not change or inflate the existing declaration/call/region fact floors.

Schema 20 keeps #302's reference storage contract: `native_version_references` is `WITHOUT ROWID`, keyed by `(vid, owner_syntax_id, ordinal)`. Equal spelling and lookup keys store a NULL lookup key and reconstruct it as spelling. Reuse preserves the immutable document family; bounded retention deletes references by their tuple key, not `rowid`. Disposable older indexes are recreated, never migrated.
