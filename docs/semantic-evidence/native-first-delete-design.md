# Native-first on DELETE — step 3 design

**Proposal before code; refs #620.** Stack: `perf/011-native-first-delete` on #654 (`89cf62b8`). No production code, Cargo or runtime changes. #654 qualification remains behind #657, main green and the owner’s queue gate; old measurements do not qualify this implementation.

## 1. What publishes first

[The owner chose DELETE](https://github.com/SquashMerge/trellis/issues/620#issuecomment-6610327636). Implement the earlier [native-first ruling](https://github.com/SquashMerge/trellis/issues/620#issuecomment-6586506796), not the WAL overlay.

**N:** atomically commit validated captured source, native facts, graph/class projections and the current pending-semantic target in `index.db`. Include affected document/producer selections, native Revision, extraction context and selected raw-input identities. Do not decode/join the full retained artifact before this commit. N is a complete readable native head, not partial native data.

**S:** stage/validate retained semantic catch-up outside N’s write transaction, then atomically commit all selected-producer results, a new paired pin and target clearance against exactly N and its selected inputs. Advance `indexRevision` within the same `indexGeneration`, retaining N’s native Revision and document versions without recapture. N and all retained pins stay immutable. Reuse bounded join/streaming-write machinery, not explicit import’s new-raw/admission behavior or batch/report identity changes.

## 2. Exact read policy proposed

- Source and native symbols/structure return committed bytes/measurements and the selected pin. Never read edited source from disk to manufacture a faster result.
- Sequence, call graph/incoming calls, references, semantic symbol lookup and semantic rules use only verified current source associations, current target authority and required destination provenance. No query family traverses an older pin’s target bindings. Raw capture basis may appear as historical metadata, not N target authority or fresh evidence.
- Explicit pending document/producer selections return per-document `catchingUp` through web, CLI and MCP; queries use labelled partial/native fallback, never a negative semantic conclusion. No pending label alone authorizes mixed revisions. Worker status remains `catchingUp:true` while the current target is outstanding.
- The native fast path may reuse unchanged semantic evidence only through an already validated revision-scoped eligibility record bound to the selected raw-input IDs, document version/context and current target authority. Eligibility is a keyed lookup plus equality checks: no SCIP decoding, full-input validation, target search or semantic join in N. A missing/invalid eligibility record means pending, regardless of document size; building that record belongs to bounded S staging. A document/context witness alone reuses **source association only**, not old bindings or freshness. Ordinary rejoin keeps required `possiblyStale` labels. Preserve #657’s exact-native-destination freshness grant: it cannot follow a later native revision, but may survive a same-native semantic-only copy as #657 allows.

**Owner question:** confirm conservative pending fallback when unchanged evidence cannot be validated cheaply, or require a separately defined older-basis projection. This is a proposed narrowing of the earlier unchanged-evidence continuity requirement, not inferred permission. No older-basis query exception is designed here. Pinned N keeps its recorded pending/partial state after unpinned reads advance to S.

## 3. One owner transition and bounded catch-up

The checkout worker remains the sole publisher under Decisions [0008](decisions/0008-daemon-sole-writer.md) and [0009](decisions/0009-checkout-worker.md). Recovery still opens the queue, confirms old-root settlement, reconciles startup, then claims FIFO. Preserve FIFO → watcher → FIFO ordering.

**Proposed boundary:** validated N finishes native startup reconciliation, an ordinary native-index request and the watcher generation its capture covers—not semantic completion. Explicit semantic-import requests still finish only after their semantic commit. Derived S is maintenance below accepted FIFO/watcher work; no second actor publishes.

At N commit, replace the single current semantic target. A maintenance unit opens/resumes a private disk stage, handles one document or its bounded work budget, checkpoints stage identity/cursor and returns to worker selection. Surviving state is N/native Revision, selected-input IDs, stage paths, cursor and bounded counters, not full native/source maps. Close main-index read snapshots before yielding and before S’s final write. Each unit must acquire a coherent captured/raw/target snapshot and recheck root, exact head N and inputs; recheck again at the owning S commit. A newer **native Revision** supersedes obsolete staging. Any intervening semantic-only pin also fails the exact-head check, but is not native supersession: the worker re-reads the marker/selections; if that publication fulfilled the target it disposes its own stage, otherwise it restages against the current pin while preserving the same native target and validating inputs. It never promotes an obsolete CAS result or overwrites an explicit semantic import. Cancellation/drop discards only its stage and releases pin resources without clearing a successor target. No timeout or failed lock probe proves completion.

**Implementation gap:** #654’s `bounded_rejoin::publish` currently joins inside the native transaction, and `join_staged_using` is synchronous—not a resumable worker API. Validate the phase/document continuation design against those APIs before implementation; no resumability is implemented or claimed by this note. Cancellation checks alone do not yield to FIFO/watcher. Do not transplant the historical prototype’s whole retained native/source allocations. Retention protects inputs while referenced; existing retirement priorities remain.

## 4. Recovery, intentional pending and contracts

N’s pending marker and raw-input identities commit with N, not in another database. S compares/clears that exact marker in its semantic commit. Transient contention uses existing bounded typed retry; terminal content failure publishes an explicit diagnosed unavailable result. N remains readable. On crash, startup reconciles the durable target, discards abandoned private staging and rebuilds bounded staging; a half-written cursor is not trusted.

Only a validated explicit pending selection makes an absent semantic result intentional. Arbitrary missing required tuples, malformed markers or inconsistent target/input identities remain typed corruption/re-index failures—not guessed pending.

Before implementation, owner confirmation is required for N as H/native-request/WATCH_ACK completion, Decision 0009’s unit/maintenance-priority clarification, pending coverage/wire/partial-query semantics, and the unchanged-evidence policy above. Amend `contract-v1.md`, Decision 0002, `local-topology.md`, Decision 0009 and closed MCP/read schemas in the PR. The current atomic native-plus-semantic contract does **not** already permit this split. Keep DELETE/FULL sync; the final semantic commit/spill can still block reads.

## 5. Proof and measurement

Use deterministic hooks between N/S for pin/read labels, unchanged evidence, supersession, restart/cancellation, FIFO/watcher order and #657 freshness invalidation. Completed results must match the FULL oracle.

On the final qualified binary measure comment, body, restore and #574 Cargo-context edits: save-begin → first successful native read of edited bytes; semantic completion; unavailable reads; sampled peak daemon RSS. Record pins/modes, canonical lock, load and OrbStack. Keep **8 GiB RSS / 900 s per phase**; preserve censored failures without silent retries. “Readable in seconds” is a target, not a result. No runtime until coordinated; #654 qualification stays gated behind #657.

## Addendum — approved older-basis projection (2026-11-03)

[Owner ruling #620](https://github.com/SquashMerge/trellis/issues/620#issuecomment-6610642350) approves native-N completion, lowest-priority resumable worker units and per-document pending/partial reads. It **supersedes section 2’s conservative fallback and the outstanding approval questions above**. Unchanged documents must keep their prior semantic evidence; a missing newly minted N eligibility record is not a reason to hide it. Implement this addendum after relaying its summary; no further design GO is required for faithful implementation. Explicit semantic-import completion remains its semantic commit.

### Eligibility and actual dependencies

Let P be the previous validated semantic pin selected for a producer, and N the current native pin. N records a projection from P, not a new semantic publication or fresh binding. A document/producer is eligible when it exists at both pins with the same `revision_documents.vid` (covering captured source hash, native extraction context and native producer identity), language/path/source-set identity, and its stored evidence does not depend on changed inputs. Native extraction context does not include external toolchain/config/dependency inputs: compare the relevant toolchain/config/dependency context at validated destination P against N, separately for the recorded producer/language/source-set scope. Do not compare the immutable original capture basis directly with N for pending eligibility: a capture-to-P mismatch already present at P stays historical freshness, not newly pending. Compare captured/indexed identities, never live filesystem contents.

The changed set includes added/removed/replaced documents and changed relevant extraction/producer context. Compute actual dependents from P’s stored evidence: symbol declaration targets; declaration join candidates; reference declared/candidate targets; call declared/candidate/possible-dispatch targets; and both endpoints of type relationships. Include a lookup dependency only when a validated producer-specific mapping identifies its scoped inputs. Current `semantic_basis_lookup_dependencies` strings have no guaranteed declaration-bucket mapping, and native reference lookup keys are not SCIP SymbolKeys; do not invent name-only equivalence. Unresolved/ambiguous/external P claims without such mapping remain explicitly historical basis-P claims, never current resolution or absence proofs. A newly introduced declaration must not silently turn that historical claim into a current internal binding. Follow dependencies transitively only where a stored evidence record actually consumes another evidence result. A target document being pending for its own outgoing evidence is not by itself a dependency of all its callers: check that later edge only when traversed. A mere file-level import or shared source set is not grounds for invalidating unrelated documents. Lookup-key records alone are not a full dependency closure. Context changes affect the evidence that records that context, not an arbitrary global fallback.

The pending set is changed documents plus those actual dependents, at document/producer granularity. Evidence absent/not requested/failed at P keeps its recorded status; this projection does not manufacture evidence. Missing required stored tuples remain corruption, not pending. Materialize/index reverse dependency associations from validated semantic publication so N uses set-based indexed invalidation; do not decode/rejoin raw artifacts or scan all proof bytes inside N. All recorded target alternatives participate; checking only a chosen resolved target is insufficient. Do not require a new speculative producer-resolution bucket subsystem to serve honest older-basis evidence.

### Labels and query families

Web, CLI and MCP expose projection metadata: the requested/current paired pin N, `semanticBasisPin: P`, P’s native Revision identity, and `semanticStatus: olderBasis`; pending documents instead carry `semanticStatus: catchingUp`. Preserve original producer/capture/proof basis and original freshness as historical metadata, but projected evidence’s effective freshness is **never `fresh`** (at most `possiblyStale`, retaining `stale` where applicable). Do not rewrite P targets’ native Revision to N or carry #657’s exact-native freshness grant across N.

Semantic symbol/declaration lookup, references, incoming calls/call graph, sequence and semantic rules all expose eligible P evidence with these labels. Source/native structure remains N. A query response is explicitly a native-N result with an authorized basis-P overlay, not an unlabelled mixed pin. Every semantic row/target must retain its basis, including nested sequence steps and rule evidence; a top-level label alone is insufficient if nested evidence can be detached. Results that also touch pending evidence are labelled partial. No empty/pending/older-basis result proves current semantic absence.

### Traversal boundaries, pins and supersession

Before each semantic hop, require the source document and each internal target/candidate/dispatch/type endpoint to be eligible against N. Read P’s target identity as P authority only. A changed or dependent endpoint is a hard semantic boundary: do not follow that edge as current, resolve it by name against N, or substitute a current target silently. Return a labelled partial boundary and, where supported, a separately labelled native-N fallback. External targets stay external basis-P claims; they are not upgraded to current internal resolutions. Multi-hop graph/sequence and rules apply the check at every hop, not just the initial document.

Record and retain the selected basis P with N’s durable pending target in the same index transaction. Later native N2 recomputes eligibility against that validated basis (not a chain of unvalidated overlays), so restore/superseding edits remain correct without unbounded revision backlog. Pin retention protects P and selected raw/captured inputs while referenced, including retained pending pins; a retained N never changes when S publishes. S atomically publishes current validated rows and clears only its exact target. A competing semantic-only publication causes exact-head CAS failure and marker re-read, not native supersession or permission to overwrite an import.

Add tests for unrelated unchanged evidence remaining visible; direct/candidate/lookup/transitive dependents pending; changed-target traversal cuts; no fresh promotion; nested basis labels; superseding edits/restores and retained-pin immutability. Keep DELETE, the 8 GiB/900 s bounds and the #657/main/user qualification gates unchanged.
