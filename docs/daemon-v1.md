# Rust daemon v1

> Current language update: native Java and Python navigation/static sequences are now available.
> See [support and boundaries](java-python-support.md). Historical first-pass limits below remain dated.

This is a runnable foundation, not the complete Trellis product. It implements explicit
full JavaScript indexing, SQLite snapshots, a loopback API and an inspection client.
No provider, ACP agent, shell, semantic indexer or source package script runs implicitly.

## Run a syntax-only workspace

```sh
cargo run --locked -- index --workspace /path/to/repository
mkdir -m 700 -p "$HOME/.trellis-private"
cargo run --locked -- serve --workspace /path/to/repository \
  --token-file "$HOME/.trellis-private/token"
```

Open http://127.0.0.1:8877/. Read the private token file at the path printed by `serve`
and paste its contents into the Connect form. The token itself is never printed by the
daemon. `--token-file` is required and must be outside the selected checkout. The
disposable path-keyed index uses fixed per-user cache locations. A Git workspace UUID marker is written inside the selected Git directory;
there are no other checkout topology writes.

`serve` does **not** index at startup. Use **Index workspace** to refresh; **Refresh status
& view** only reloads the already published data. Ctrl-C or SIGTERM cancels an active index job and
stops serving. A cancellation request cannot undo a revision already committed.

`--state-dir` is removed; there is no placement override or automatic old-state migration.
Keep the token at an explicit private path outside the selected checkout and fixed topology.
Move old in-checkout token data manually with Trellis stopped. Retired saved records and
Jev/ACP ledgers remain in place and ignored, not inspected, migrated or deleted.
The example above creates a private parent; a new token file is created with private permissions.

`--bind 127.0.0.1:0` selects a free port. Non-loopback addresses are rejected. The first
HTTP/token implementation requires Unix permissions; Windows daemon authentication is
not implemented. SQLite and tree-sitter build with the native C toolchain.

## Use the existing semantic snapshot

These artifacts were generated by the extraction spike and are ignored, not portable
fixtures guaranteed to exist in a new checkout. They are present in this workspace.

```sh
cargo run --locked -- index \
  --workspace tests/fixtures/extraction/inputs/feature-factory \
  --scip tests/fixtures/extraction/feature-factory.scip \
  --manifest tests/fixtures/extraction/feature-factory.hashes.json

mkdir -m 700 -p "$HOME/.trellis-private"
cargo run --locked -- serve \
  --workspace tests/fixtures/extraction/inputs/feature-factory \
  --scip tests/fixtures/extraction/feature-factory.scip \
  --manifest tests/fixtures/extraction/feature-factory.hashes.json \
  --token-file "$HOME/.trellis-private/token"
```

Browse to `transition`, select it, and inspect its immediate call sites. Read source
from a call. Deeper traversal and callback navigation are
explicit options. The client collapses detailed resolution evidence by default.

To regenerate missing SCIP artifacts, use the **explicit** extraction-spike workflow in
[its README](../tools/extraction/README.md). That separate workflow runs the pinned
SCIP indexer; the Rust daemon does not. No model call is needed.

### Import trust and freshness

`--manifest` accepts a flat JSON object of repository-relative input paths to SHA-256
hex strings. It must describe the exact unchanged inputs used to produce the supplied
binary SCIP file. **It is trusted paired evidence, not cryptographic attestation of how
or when SCIP was generated.** Do not make a new manifest for old SCIP after editing code.

The compared scope includes discovered `.js`, `.mjs`, `.cjs` and these present root files:
`package.json`, `tsconfig.json`, `jsconfig.json`, `package-lock.json`, `yarn.lock`,
`pnpm-lock.yaml`, `bun.lock`, `bun.lockb`. Changed, added, removed or skipped inputs disable
semantic resolution for the snapshot. No manifest means syntax-only results. A malformed
SCIP/manifest produces a diagnostic and syntax-only results rather than invented targets.

Transitive config, installed dependencies, environment and indexer versions are not
attested. Regenerate the pair when they change. Explicit document position encodings are
honored; unspecified encodings use the tested scip-typescript UTF-16 convention. This is
not a general compatibility claim for every SCIP producer.

Parse-error files retain recovered syntax with unavailable semantic provenance. Global
`semanticState` reports manifest freshness, not parse completeness or live working-tree
freshness. There is **no watcher**: the source may have changed since indexing.

**Status of a published import (#467).** `trellis status` and `GET /api/status` read the
head revision's published semantic producers per language (owner ruling 2026-10-30, #483,
amending #392/#409): each language uses the sole published producer whose profile covers
it. `semanticLanguages` lists every indexed language as `{language, semanticProducerId,
semanticNote, semanticState, calls, internal, external, ambiguous, unresolved}` from that
producer's selected bindings. `semanticState` is `fresh`, or `stale` when any selected proof
is not fresh. It is `unavailable` when no selected complete or partial coverage exists.
`internal` counts calls resolved to an internal declaration, `external` external calls, and
`ambiguous` ambiguous calls. Each call counts once, even when an ambiguous call publishes
one row per provenance. `unresolved` counts the language's remaining measured calls. A
language that none or several producers cover has a `semanticNote` (`semantic producer does
not cover this language; showing syntax` or `multiple semantic producers for <language>;
showing syntax`), `unavailable` and syntax-only counts. `stats` is the combined total:
`stale` if any language is stale, else `fresh` if any is fresh. The top-level
`semanticProducerId` names the producer when every selected language shares one, and
`semanticNote` joins the multiple-producer notes. With no producer published,
`semanticLanguages` is omitted. When no indexed language has a producer, `semanticNote`
says why, `semanticState` is `unavailable` and the counts stay syntax-only.
`GET /api/methods` and `trellis symbols` mark each symbol's `provenance.semantic` with its
document language's producer state.

## Data and identity contract

Public JSON uses camelCase. `src/model.rs` is the canonical Rust contract.

- Source is captured once per file with SHA-256. API source reads never open a requested
  filesystem path. They return indexed bytes from the SQLite snapshot.
- `SourceRange` has UTF-8 byte offsets `[startByte, endByte)` and **1-based lines and
  UTF-8 byte columns**, with the end position exclusive. Columns are not browser UTF-16
  offsets or grapheme positions. Source highlighting in the inspector uses whole lines.
- Symbol kinds: `module`, `function`, `method`, `class`. Global resolved IDs retain SCIP
  strings. Local SCIP IDs are scoped by document **and source hash**. Parser-only IDs
  include the path, source hash, offset and syntax kind. Any file edit can therefore
  change local/provisional IDs; never attach old evidence to a different function at a reused offset.
- Call sites retain distinct identities, caller, callee text, source span, measured
  candidate symbols, callback references and control-region IDs. Resolutions are
  `internal`, `external`, `unresolved`, `ambiguous`. “External” means outside the indexed
  callable nodes, not necessarily a known third-party package.
- Candidates are evidence, not necessarily graph nodes or callable targets. Callbacks
  remain separate function bodies. Passing a function is not a call to that function.
- Native class nodes allow references to known class constructors. Instance-field
  initialization evidence belongs to the class under an `instance-initializer` boundary,
  not to the enclosing class-definition function. Constructor dispatch/timing is not
  modeled. Static initializers and computed keys remain in the definition context.
- Control regions cover tested if/else, ternary, short-circuit RHS, loops, try/catch/finally
  and switch cases. They are lexical context, not a complete control-flow graph.
- Call lists use source order, including numeric offset ordering before display caps.
  `f(g())` is not execution-ordered. Never label this output a sequence diagram or trace.

## Query contract

The retained CLI `trellis query` uses the shared query service with these fields.
The former browser `POST /api/query` route is removed:

```json
{
  "seed": "an indexed symbol ID",
  "depth": 1,
  "maxNodes": 40,
  "maxCalls": 200,
  "includeCallbacks": false,
  "excludePaths": [],
  "semanticProducerId": "optional; `--semantic-producer-id` on the CLI"
}
```

Depth 0 returns only the seed. Depth 1 inspects its direct call sites and includes their
known internal targets without expanding those targets. External, ambiguous and unresolved
sites remain boundary records. Enabling callbacks allows navigation into their definitions
when depth permits; it never creates synthetic call edges. Excluded paths are literal
prefixes, not glob or regex patterns. The seed remains in the result even if excluded.

Limits: depth 0–5, nodes 1–150, calls 1–500; at most 100 excluded prefixes of 1,024 bytes
each. Traversal is cycle-safe. Truncation is explicit. `omittedNodes` counts discovered
omitted targets, not all unseen reachable nodes. A retained call may point to a target
outside the displayed node budget; do not invent a connecting box/edge to hide that.

A result includes `revision` as the complete `{indexGeneration,indexRevision}` pair,
the effective query, `nodes`, `calls`, `regions`, `truncated`, `omittedNodes`, `warnings`
and `semantic`. The pair and all facts are read in one SQLite transaction.

`semantic` (#467) applies the per-language producer selection at that revision (owner
ruling 2026-10-30, #483). An explicit `semanticProducerId` (1–512 bytes, no NUL) must be
published there: an empty or oversized ID fails `invalid_argument`, and an unpublished one
fails `producer_unavailable`. Without one, each document uses the sole published producer
whose profile covers its language. A seed language that none or several cover leaves the
view syntax only, with `semantic.note` `no semantic producer published; showing syntax` or
`multiple semantic producers for <language>; showing syntax`; producers are never merged. A
producer that does not cover the seed's language gives `semantic producer does not cover
this language; showing syntax`. The walk follows a call whose binding has `boundaryReason`
`none` to its exact target, as the call graph does: depth 1 adds the seed's targets, and
each further level inspects the previous level's calls (#483). Otherwise `semantic` is `{producerId, note: null, bindings}`. Each
binding is `{callId, boundaryReason, targetId, freshness, binding}` for a returned call
that has one. `binding` is the published contract-v1 `CallBinding`: resolution, declared
target, the whole candidate union of an ambiguous call, dispatch and provenance ID. It is
selected by the reader that the call graph, sequence and line navigation share. `boundaryReason`
is that engine's reason, where `none` means the graph would traverse the call. `targetId`
is a resolved binding's declared internal target, located exactly in this snapshot and not
stale. With a `dispatch` boundary, `targetId` is the declared target, not a proven callee. Calls
with a binding, and the seed when its document's selected coverage is complete or
partial, carry `provenance.semantic` `fresh` or `stale` instead of `unavailable`. Forward both fields to pinned
shared source/symbol lookups; a stale pair returns a typed conflict. A bare numeric pin is invalid.
Only the current snapshot is stored server-side; this is not historical time travel.

## Storage and publication

The disposable `<cache>/indexes/<root-key>/index.db` holds normalized files, nodes,
calls and regions, plus typed JSON row payloads and paired revision metadata. Foreign keys
enforce file/caller/owner relationships.
Graph validation checks source hashes/ranges, unique IDs, internal targets, containment
and region references before publication. Structural statistics are recounted.

A writer takes `BEGIN IMMEDIATE`, checks its expected current `{indexGeneration,indexRevision}`
pair, inserts the full replacement graph and commits once. Error or cancellation leaves
the prior graph visible. A new disposable index gets a new random generation; ordinary
publication keeps the generation and advances the numeric revision. Deleting and recreating
the index can reuse a revision number, but never its generation. There is no durable
revision allocator in `workspace.db`.

Saved views, notes and their persistence are retired by the [owner ruling 2026-10-24, #305](https://github.com/SquashMerge/trellis/issues/305#issuecomment-6394175295).
Existing record databases, sidecars, locks and provider trees remain in place and ignored.
`trellis forget` is removed. `trellis gc --report` prints a read-only derived-index inventory,
without opening or enumerating saved records. Never unlink a live SQLite database.
The tests demonstrate transactional failure/cancellation, not simulated power loss.

Search is bounded literal substring search, prioritizing exact symbol names. It is **not
FTS** yet. Full rebuilds are sequential, not incremental or Rayon-parallel. These choices
keep the first slice simple; measure a larger workload before changing them.

## HTTP and security

Every `/api` route requires `Authorization: Bearer <token>`. Tokens are 32 random bytes
encoded as 64 lowercase hex characters, stored in a private owned, non-symlink file.
Source databases are private too. The browser keeps its token and source cache in memory;
Disconnect clears them. There are no cookies, query-string credentials or provider keys.

Host must match the bound loopback socket or `localhost` on that exact port. A supplied
Origin must match one of those same local origins. Arbitrary web origins, duplicate
credentials/Host headers and permissive CORS are not accepted. Responses use no-store,
CSP and nosniff. JSON requests are capped at 1 MiB. No frontend dev-origin exception exists
in this first pass; use the embedded client or same-origin proxying later.

Only the configured workspace can be indexed. No API accepts another root or arbitrary
file reads/executables. Discovery respects ignores, skips hidden/build/
dependency/state directories and does not traverse symlinks. Unix reads use no-follow
and post-open checks. **This is not a capability-based sandbox against hostile concurrent
ancestor-directory replacement**, nor a defense against another process with the same
user's privileges. Do not expose it through a tunnel or untrusted proxy.

Caps: 2 MiB per source by default (`--max-file-bytes`, up to 16 MiB through the CLI),
256 MiB aggregate source, 100,000 discovered source files, 256 MiB SCIP and nesting under
512 levels. Oversized/unreadable individual files are diagnosed; aggregate limits fail
without publishing. These are guardrails, not a proven hostile-input resource sandbox.

| Method | Path | Response / behavior |
| --- | --- | --- |
| GET | `/healthz` | Public `ok`, version; no workspace details |
| GET | `/api/status` | Current `IndexStatus` (paired revision, numeric part 0 if empty) |
| GET | `/api/checkouts/{rootKey}/status/head` | Fixed-size digest of the same status: `{workspaceRoot, revision, catchingUp, indexedAt}`. The browser polls this to compare the shown revision with the head (#527). |
| POST | `/api/index` | Empty body or `{expectedRevision:{indexGeneration,indexRevision}}`; 202 background job |
| GET | `/api/jobs/current` | Latest job or null |
| GET | `/api/jobs/{id}` | Job, or 404 |
| POST | `/api/jobs/{id}/cancel` | Request cancellation; completed jobs stay completed |
| GET | `/api/source?path=...&indexGeneration=...&indexRevision=...` | `{revision, file}`; cached source only, optional complete pair guard |

Unknown request fields are rejected. Retired Tools endpoints use the ordinary unknown-route response; there is no compatibility API for saved records or providers.

Errors use `{error:{code,message}}`, without raw SQL or source-bearing diagnostics.
Expect 401 for missing credentials, 403 for Host/Origin rejection, 404 for missing data,
409 for stale paired pins/active jobs, 413 for body limits, and 400/422 for invalid input.
Jobs use `running`, `cancelling`, `completed`, `cancelled`, `failed`, with progress,
optional published revision/error, and epoch-millisecond string timestamps. Only the
latest 100 job records are retained in memory; restart does not resume old jobs.

For DTO details, see [the frontend handoff](daemon-v1-api-handoff.md).

## Current limits

The Tools tab, question planning, Jev selection, ACP answers and saved records are retired.
Java/Python native indexing, class diagrams and static sequence diagrams remain available. There is no watcher or #39 reconciliation/read fencing, automatic
GC (#16), rich durable anchor model (#38), TypeScript grammar, LSP, terminal, Tauri
shell, ORM or external database connection. See [local topology](local-topology.md)
for the shipped-versus-future boundary.
