The benchmark uses one selected checkout at a time and authenticated loopback HTTP. The first revision request follows index completion and has a fresh daemon-owned source-only metrics memo. Warm repeats the **same pin** without reindexing. Measurements use `time.perf_counter()` from request initiation through full body receipt and JSON parse. Response bytes are raw, uncompressed received body bytes; neither truncation nor aggregation-only substitution is used.
- Default `revision` DTO: `aggregate=sum`, all 12 canonical selected metrics (`loc,sloc,commentLines,cyclomatic,cognitive,maxNesting,halstead,maintainabilityIndex,fanOut,fanIn,parameters,exits`), all file rows, all directory rows including root, and `declarations:[]`. `callablesComputed` is the sum of every file row's `declarationCount`; computing callables does not require returning declaration rows. A separate default `file` scope request checks full declaration rows.
- Server constraints: 64 MiB serialized metrics response cap, 300 s `revision` work deadline. Medium cold above approximately 5 s is an owner note, **not** a CI/performance failure.
