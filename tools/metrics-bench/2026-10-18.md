# `metrics:v1` synthetic-cohort benchmark — 2026-10-18

The full default 1,000-file medium `revision` DTO completed over authenticated HTTP and daemon-routed CLI. The full default 10,000-file large HTTP **and CLI** requests **did not complete**: both returned typed `deadline_exceeded` at the unchanged 300-second work deadline, even with the approved `--release` build. The HTTP 73-byte error body and CLI zero-byte stdout are not full response sizes. Both independent pinned Java file-scope requests completed. Speed is **reported, not gated**, under the [issue #120 owner ruling](https://github.com/SquashMerge/trellis/issues/120#issuecomment-6244174345). No sample, deadline change, or aggregate-only shortcut is used. Performance follow-up: [issue #174](https://github.com/SquashMerge/trellis/issues/174).

## Environment, sources and boundaries

- macOS 27.0.1, Apple M5 Pro (arm64; 18 physical/18 logical cores), 64 GiB RAM. Build commands: `RUSTUP_TOOLCHAIN=1.99 CARGO_TARGET_DIR=/tmp/trellis-factory-120-bench-target cargo build --locked --bin trellis` for the disclosed initial debug attempt, then `RUSTUP_TOOLCHAIN=1.99 CARGO_TARGET_DIR=/tmp/trellis-factory-120-bench-target cargo build --locked --release --bin trellis` for the approved rerun.
- `node tools/synthetic-cohorts/generate.mjs --out /tmp/trellis-factory-120-metrics-bench/generated`; seed `trellis-synthetic-cohorts-v1` from `tools/synthetic-cohorts/manifest-v1.json`. Medium: **1,000 files / 16,777,216 source bytes**. Large: **10,000 files / 134,217,728 source bytes**. The selected workspaces are the *entire* `generated/medium` and `generated/large` trees. The canonical generator also makes small; small was not benchmarked.
- Every timed revision query requests `scope=revision` with default `aggregate=sum` and **all** 12 metrics in canonical order: `loc,sloc,commentLines,cyclomatic,cognitive,maxNesting,halstead,maintainabilityIndex,fanOut,fanIn,parameters,exits`. There is no `metrics` selection query parameter or filter. A valid full response has all 1,000 or 10,000 file rows, all 9 or 44 directory rows including root, and `declarations:[]`. All selected native callables must still be computed; the observed callable count sums all file `declarationCount` values. The separately timed pinned Java `file` request returns declaration rows and **does not substitute** for revision timing.
- All attempts use isolated external `HOME`/cache/index/token paths, a loopback authenticated production `trellis serve`, and the same retained pin for cold/warm within each transport. A new daemon has an empty source-only metrics memo. CLI is the daemon-routed `trellis metrics --json`; it does **not** open a standalone Store. The runner starts timing at request start and stops after the **entire response is received and parsed as JSON**, using `time.perf_counter()`. HTTP byte counts are raw, full, uncompressed response-body bytes. CLI byte counts are the complete pretty-printed JSON stdout bytes. A typed error body is labeled error bytes, not a full DTO length. The daemon's 64 MiB metrics response cap and 300-second revision work deadline remain unchanged. Setup/index timing is outside measured requests.
- `catchingUp:true` is recorded, not removed or used as an excuse to claim an estimated time. Watcher activity and other process load affect comparisons; these are one-machine observations, not a performance promise. Medium cold above approximately 5 seconds is an owner note, not an acceptance gate.

Index generation `e8a17415-0fa6-435c-822c-5df7b847fe3d`, retained revision `2`. Revision rows were all **1,000 files, 9 directories (one root), zero declaration rows and 73,375 summed callables**; default 12 selected metrics. These are full payloads, not estimated or partial counts.

| HTTP revision warm, same daemon/pin | 39.075979 s | 639,558 HTTP body bytes | true | HTTP 200, full DTO |
| CLI revision cold, restarted release daemon/memo | 107.417671 s | 1,089,648 stdout bytes | true | exit 0, full DTO |

Do not infer that an optimized binary is intrinsically slower: these requests ran at different times with `catchingUp:true` and changing watcher/index activity. Both medium cold measurements exceed the approximately 5-second owner-note threshold. The successful full HTTP medium body is below 67,108,864 bytes (64 MiB).

| Full default 10,000-file revision request | Result | Full DTO bytes / file rows / directory rows / callable total |

| HTTP warm | **NOT COMPLETED** — not run after cold failure | **not observed** |
| CLI cold | **NOT COMPLETED** — typed stderr `Error: deadline_exceeded` after 300.148796 s, exit 1 | **not observed** (stdout had zero bytes) |
| CLI warm | **NOT COMPLETED** — not run after cold failure | **not observed** |

An authenticated `GET /api/checkouts/c5daa84aae42c905ae221cea2e33f17de6e3af70e1877dbc63a1668087cd93f4/metrics?indexGeneration=caa9c854-a489-4b72-969c-cae874135ceb&indexRevision=2` used a **fresh release daemon/memo** and the default revision DTO with all metrics. It returned **HTTP 408** at **300.295423 s**; exactly **73 bytes of typed error body**, not a full response. The exact parsed body was:

```json
{"error":{"code":"deadline_exceeded","message":"Storage is unavailable"}}
```

The HTTP cold request produced **no 10,000-row payload**, so there is no large full-response byte length, directory-row count from an actual DTO, or computed callable total to report. HTTP warm is **not run**: a failed cold response cannot establish the requested successful full cold/warm pair. The independent default `file` request pinned to the same revision did complete: `java/Clarge0501.java`, HTTP 200, `catchingUp:true`, **0.890072 s**, **47,904 body bytes**, one file row and **72 declaration rows**. This file result is not a whole-revision result. The initial external log labeled its phase `after warm`, though the cold revision had failed and no warm request was sent; the runner's label is corrected for subsequent attempts.

A separate, freshly restarted release daemon with an empty memo executed daemon-routed CLI `metrics --json --workspace /private/tmp/trellis-factory-120-metrics-bench/generated/large --pin caa9c854-a489-4b72-969c-cae874135ceb:2` with default `scope=revision`, `aggregate=sum`, and all metrics. The full cold attempt exited **1** at **300.148796 s**, **zero stdout bytes** and exact stderr `Error: deadline_exceeded\n`. This is a typed **not-completed** result, not a full DTO; CLI warm was **not run** after failed cold. Its independent pinned CLI file request on `java/Clarge0501.java` succeeded with exit 0, `catchingUp:true`, **0.878965 s**, **83,724 complete stdout bytes**, one file row and **72 declaration rows**. It cannot replace the missing 10,000-file revision DTO. No actual full large response size, full directory-row count, or computed large callable total was observed; do not turn the target of approximately 712,120 callables into an observed result.

## Disclosed debug setup and earlier timing

The first build was unoptimized. It is **not** a release result, but its measured data and setup failures remain visible:

| Debug attempt | Pin | Elapsed wall time | Bytes | Rows / typed outcome |
| --- | --- | ---: | ---: | --- |
| Medium HTTP cold full revision | `e8a17415-0fa6-435c-822c-5df7b847fe3d:2` | 31.917957 s | 639,559 body bytes | 1,000 files, 9 dirs incl root, 73,375 callables, `declarations:[]`, HTTP 200, `catchingUp:false` |
| Medium HTTP warm same pin | same | 24.553823 s | 639,559 body bytes | same full DTO, HTTP 200, `catchingUp:false` |
| Medium HTTP pinned Java `file` | same | 0.050142 s | 48,225 body bytes | one file, 72 declarations, HTTP 200 |
| Large HTTP cold full revision attempt | `caa9c854-a489-4b72-969c-cae874135ceb:2` | 300.008181 s | **73 error-body bytes** | HTTP 408 `deadline_exceeded`; no full DTO |

The initial medium runner invoked `trellis index --workspace <medium>` and received `Error: outcome_unknown` after 60.596825 s because the CLI index wait expired. Its durable job continued and finished `state=done`; the setup-only runner also initially mistook `done` for `completed` and exited before metrics. Both were fixed by resuming the **same** medium index job, not reindexing for a measurement. The large HTTP index job `1b49a551-6238-4141-9102-27ecaefc1f23` exceeded the runner's first **1,200 s setup backstop**, was observed alive with index growth, and completed `state=done` after **1,802.535 s** from admission. This setup bound is distinct from the 300-second metric work deadline. The approved release runs reused these completed external indexes and retained pins; daemons were stopped between cold transports to empty memo state. Startup watcher refreshes advanced medium head beyond revision 2; retained pin 2 was explicitly supplied and successfully selected.
